# M3 原型发现（诚实版）

## 能跑的
- 抽取器对 11 页产出草稿，全部零错误通过校验；机械管线成立。
- 抽取出的 fields-draft 字典、分页统计可用。

## 不能比的
- **auto vs hand 的告警对比无效。** auto 草稿是"文本扫货"：linear 草稿 1463 行 vs 人工 146 行（10×），
  把演示应用 UI（"Copy git branch name"、"DRV-8852 1 / 84"）都收成故事线/动作。告警下降来自噪声注入，
  不是结构更好。**在结构质量指标存在之前，auto-vs-hand 对比不具资格。**

## 根因缺陷（F-023）：语料 text 字段被截断
- `corpus/*/nodes.json` 的 `text` 只存了 ~64 字符（"…Designed for t"），而 `name` 是全量。
- 后果：一切基于 text 的抽取/评测都被截断质量封顶。
- 修法：① 抽取器取 text/name 的较长者（立即可做）；② capture 管线修复 text 截断（下次重抓生效）。

## 下一步门槛（M3 真正的验收）
新增**结构质量指标**（评估侧，不加语法概念）：
- chrome 比例：动作标签匹配 UI 操作词（copy/open/close/menu/复制/打开）的占比
- 截断率：文本在语料中被截断的比例
- intent 覆盖：组节点有 `_intent` 的比例
- 松散动作比：无目标、无 label 的动作占比
这些指标立起来之前，auto 抽取只能当"覆盖率上限的粗探针"，不能当质量声明。
