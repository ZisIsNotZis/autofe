## 1. 轴即语义（不可由宽度决定）

- **同一行** ⇒ 成员**可比**：同类、同形、同粒度，可横向对照。
- **同一列（堆叠）** ⇒ 成员是**顺序**或**并列但不可比**的区块，各自独立成立。
- 因此：**列数不能由容器宽度决定**，必须由语义决定；宽度只决定"排得下几列"。

推论（引擎必须遵守）：
1. 只有"可比"的成员才允许进入行布局；
2. 不可比 ⇒ 堆叠，每块**自带标题**；
3. 无标题的堆叠块必须显式区隔，否则会被读成上一个标题的下属内容；
4. 行内任何成员不得因列数过多而被压到"一行一两个字"——**宽度不足就减少列数，不是压窄**。

## 2. 可比的判据（可计算，引擎自判）

成员集合 S 进入行布局当且仅当：

| 判据 | 含义 | 阈值 |
|---|---|---|
| **同形** | 事实键/子节点形状集合的两两 Jaccard 均值 | ≥ 0.6 |
| **同粒度** | 成员文本长度（最短项以 40 字为分母下限；空文本项不做比值判定） | 最大/最小 ≤ 4× |
| **结构可比** | 同类条目能够进入共同形态；不是实际可读性的证明 | 文本 ≤ 400 字、子节点 ≤ 2 |

任一不满足 ⇒ 该集合是**区块序列**，堆叠渲染。纯标签集合另走清单/控件规则，真实数据表与声明对比另走表格规则。图像比例与渲染高度不能由这些源结构判据保证，必须通过实际页面检查；不能宣称实现了运行时同高闸门。无图的编辑记录默认单列：带 `_title`/`_detail`、无图/价格/字段且有成员超过 160 字的章节集合选择 stack。有序 `_text` 段落的子件若均为该段已有文字中的来源动作标签，则同样选择 stack，不能用裸 prose 画法吞掉这些动作；工具控件、功能卡与商品集合仍按原规则判断。纯来源动作子件（只有动作，或标题等于动作 label）若 `open/navigate` 目标已声明且 label 仅归属于本节点的一条正文/引用事实，三个目标把它画在所属句内一次，不再重复输出子控件；作者元数据与来源说明的整条文本等于来源动作 label 时也复用该行内归属，不另造链接值类型；重叠标签/多事实歧义保持原状。此规则只消费已声明目标，不从文字/域名构造目标。图像占比 ≥75%、每项文本 ≤160 字的卡片大小集合可声明多列；结构可比、用 `_name` 标识且没有作者/来源/时间等记录性元数据的同类功能实体卡片也可声明多列（保留既有功能对照形态），长章节不靠容器宽度变成网格。带 `_summary` 且合计文本超过160字的命名摘录不使用功能实体多列规则；带 `_detail` 的命名功能卡仍按原有规则判断，不能为了搜索摘要而回退已接受的功能对照。400/4× 是当前既有结构可比实现的阈值，不等于运行时密度保证；实际可读性仍由页面检查证明。

反例（本轮实测）：
- 苹果 iPhone 16 六步（Finish/Storage/Trade In/Payment/Connectivity/Carrier）：字段键几乎不重叠、单格高 786px vs 1667px ⇒ 序列，必须堆叠；
- 少数派 114716 正文 17 段：非同类、长文本 ⇒ 序列，堆叠为阅读宽度；
- 36kr 频道 17 项（纯标签、同形紧凑）⇒ 真可比 ⇒ 允许行布局（chip 条）。

## 3. 横向对比 = 表格，且**不换行**

`_rel.compare` 的成员是"被对照的实体"（如各机型）。合规形态：

- **列 = 实体**（每个实体一列，列头是实体名/价格/标签）；
- **行 = 属性**（Display / Chip / Camera / Battery …）；
- 实体的个数决定列数，**不因宽度折到第二行**；宽度不足时**横向滚动**，绝不换行；
- 当前浏览对象用标记（如"当前浏览"）出现，不是重复内容。

### 3.1 位置行不是属性（明文规则）

- `_items[i]` / `_lines[i]` 是**数组元素**，不是可比属性。按下标把两个无关列表对齐是"配对"而非"对照"
  （如 iPhone 17 的`薰衣草紫色`与 iPhone Air 的`蓝色`）。引擎**不得**把位置键当作行键。
- 实体自己的嵌套集合（如机身颜色）属于**该实体**，渲染在该实体的列内；不得提升为跨实体的行。

### 3.2 退化对比表（明文规则）

`_rel.compare` 声明本身正确，但渲染出的表若是退化的，引擎**不得**输出空壳表——必须回退到该集合的
**正常形态**（deflist / product-cards / cards / 序列），并在 pipeline 的「显式降级清单」里输出**带理由**的一条
（与 D2 的 `no-comparable-attribute` 并列）。

- **行键集** = 实体的类型化字段 / 角色事实 / 命名子节点（**不含**位置键，见 3.1）。
- **有效行** = 被 **≥ 2 个实体**同时声明值的行。
- **填充率** = 有值的单元格数 / (行数 × 列数)。
- **退化判据**（任一成立即退化）：
  1. `有效行 == 0` ⇒ `degenerate-no-shared-attribute`（空壳：每行只有一列有值，两列各说各话）；
  2. `填充率 < 0.4` ⇒ `degenerate-fill-rate:<rate>`（多半是空格）。
- **阈值 0.4 的论据**（轮 10 全库实测）：合表格的填充率为 1.00 / 1.00 / 0.91，退化表为 0.50；0.4 位于两者之间且留余量。
- **为何不用"有效行 < 2"**：只有 1 条有效行但填充率 1.00 的表（如 Airbnb 各维评分）是**合法最小对比表**，
  被第 6 轮验收接受；一刀切会误伤。空壳的判别落在"**一条共享行都没有**"上。

引擎把上述理由记入渲染审计（`renderWithAudit().degradations`）；地基自测（`foundation-selftest.mjs` D2b）
用构造集固定：稀疏集不进表、稠密集进表、低填充带率降级、位置集合留在列内。

### 3.3 数据表（行 = 记录、列 = 属性）的成立条件（明文规则）

`_fields` 声明的集合是**数据表**（行 = 记录、列 = 属性），方向与 §3 的对比表相反（对比表**列 = 实体**）。

- **列 = 身份列 + 已声明的属性列**。身份列 = 成员的 `_name`/`_title`（成员的“这一行是谁”），成员有名字时**必含**；
  属性列 = `_fields` 的键 ∪ 非 name 角色事实。列名只能来自已声明域字段（`vocab-fields.json` 的 `label`）——
  **绝不把内部键印成列名**。
- **成立条件**：
  - 成员有名字 ⇒ 身份列 + **≥ 2 个属性列**；
  - 成员没有名字 ⇒ **≥ 2 个属性列**，且**至少一列有已声明列标签**。
- **反例（都不是表）**：
  - **单列**不是表——那是列表；
  - **没有声明列的“看着像表格”的东西**不是表；
  - **身份列 + 1 个属性列**（“名字 + 一个值”）不是表——那是 deflist；两个属性列才够成表。
- **为什么删掉旧的“≥3 列”阈值**（轮 12 实测）：源站价目表本身常常只有 2 列（`行标签 | 价格`），例如
  `aws.amazon.com/ec2/pricing/on-demand` 的三张 2 列表（表头分别为“空 | 定价”、“数据自 Amazon EC2 传出至 | 空”、
  “（同区域传输的说明）| 定价”）。这类两列的语义是**声明过的**（域字段 + 抓取表头），且**没有身份列可丢**，
  旧阈值把源站真表一律降级成卡片。
- **成表不得丢名**：成员带名字时身份列一定进表（地基自测 F-051 固定：`cpu|memory` 这类集合若成表，实例名仍在）。
- **影响面**（轮 12）：全库 `_fields` 的列数是 `{2 列: 5 个节点, 4 列: 32 个节点}`。唯一会因本规则改变形态的
  集合是 aws 的三张 2 列表；`gov-uk`（4 列、无身份列）、`aliyun-com/product-ecs`（`.scale` 是命名子节点、
  `.instances` 走 `_rel.compare` 对比表，都不经 `renderRun`）以及其余 38 页**逐文件渲染 diff 为零**。

## 4. 控件不是内容

`_action`-only 的成员（加入购物车 / 喜欢 / 修改 / 立即领取）是**控件**，必须渲染为控件条（链接样式，可点击感），
**不得**混入 chip/内容条目。控件若有抓取到的目标地址 ⇒ `<a>`；无目标 ⇒ 保持链接观感（不造 `<button>`）。

### 4.1 一个元素的控件成一行，主 CTA 一条（轮 27 明文规则）

**实测前提（不是猜的）**：模型里**没有** "谁是主 CTA" 的标记。有的只是 F-020 的**两个元素**：

- 元素**自身的** `_action` = 这个元素自己的动作（"查看详情"；axioms §6："卡片自己的动作是查看更多信息"）；
- **子节点**的 `_action`，当该子节点除自己的标题外什么都没有时（标题就是它的控件文案），是元素**内部的按钮**
  （axioms §6 的例子原文：`"buy": { "_intent": "买是另一个故事", "_title": { "text": "购买" }, "_action": { "verb": "buy" } }`）。

因此**主次是渲染强调规则，必须由引擎画出来**（这**不是**语法变更，模型不改）：

1. **一行**：一个元素自己的动作 + 它的 `_action`-only 子节点 + 它的"标题即自身控件且无其它内容"的子节点，**同属一行**
   （复用 `.controls` 机制），**绝不一条一行**；`nodePlan` 输出的 `actionRow` 就是这一行（三个目标共享同一决策）。
2. **主 CTA（实心）只由承诺型动词认领**：该行中第一个**承诺型动词** `buy`/`preorder`/`add-to-cart`/`submit` 即主 CTA；
   **没有承诺型动词时整行没有主 CTA，全部次要**（描边 `.ctl`）——**绝不**把行内任意一个（元素的自身动作、或第一个控件）提为主。
   （轮 32 修正轮 27：旧回退“② 否则元素自身 `_action`；③ 否则行内第一个”把 airbnb 房源页的**房型属性控件**「共享」提成
   深色实心主按钮、把真正的动作「添加至心愿单」降级——比改前更错。属性类控件（共享/收藏/筛选）不是主行动。）
3. 行内只有一个控件时**不包裹**容器，控件维持原样式：单控件不是“主次选择”（没有第二个可比较），它就是该元素自身的动作，保持原形状（改动只落在真正出现“多个动作”的地方）。
4. 无目标地址的控件仍然**不造** `<button>`；行内主 CTA 的"实心"只是样式（T-101 不受影响）。

**实测效果**：`apple-com/home` 三个 hero：`Buy`（子节点，`buy`）**实心**、`Learn more`（元素自身，`open`）**描边**，且落在**同一行**；
源站即如此。全库只有一个元素同时有"自身动作 + 内部控件"时才会因此改变强调（其余页面自身的动作本来就是该行唯一控件）。

**为什么不是"元素自身的 `_action` 一律为主"**：全库 108 个"一个节点上多个动作"的样本里，页面主的 `_action` 常常是
"看更多"这类**导航**动作（36kr `查看更多资讯`、apple hero `Learn more`、bilibili `自动连播`），
把它涂成实心主按钮正是用户说的"主次颠倒"。动词的语义（"去哪看" vs "下单/提交"）才是区分主 CTA 的可用信号。

### 4.2 动作行是三个目标共享的同一个决策（轮 27b 明文规则）

`nodePlan().actionRow`（一行控件 + 每条 `{label,href,verb,primary}` + `rowConsumed`）是**唯一**的动作分组与主次决策。
三个目标**都**消费它，只各自选择画法：

- HTML：一个 `.controls` 里主 CTA 实心 `.action`、其余描边 `.ctl`（单控件不包裹，维持原样式）；
- 纯文本：**同一行并列**，多控件行里共享主 CTA 前缀 `*`（如 `[Learn more] *[Buy]`）；
- Markdown：**同一行内联链接**，多控件行里共享主 CTA 加粗（如 `[Learn more](…) **[Buy](…)**`）。

任何**渲染器不得自行分组动作**：不得出现私有的 `actionKids`/`plan.toolbar`/`actionRowOf` 之类再推导。
`axis-selftest.mjs` 的 A4 静态断言禁止私有分组，H0–H5 动态断言：同一模型在三目标下的动作**分组与主次**
必须一致（构造模型三目标逐一比对；全库 68 个多控件行的分组行数与共享决策计数相等）。

"标题即自身控件"的元素（如 bilibili 视频页 a 块）：标题链接是标题，**其余控件仍照 `actionRow` 画出**，绝不因其
titleIsControl 而吞掉同一元素上的其它控件。声明为对比的实体列也消费完整 `actionRow`；标题即 Buy 的内部子件属于列头动作组，不生成一条假的“Buy 属性行”。命名子件和集合里的纯内部控件都可进入所属元素的同一动作行。

根节点的 `buy/preorder` 是开头产品购买决策：动作紧随根事实/价格，而不被所有后续章节推到页底。无价格但有产品导语的此类根节点先画导语/购买，再画受内容框架约束的说明图；非购买类根动作仍可作为末尾 CTA。无独立事实的控件条成员只输出一枚控件，动作 label 为可见文案，不同的 name 作为可访问别名保留，不伪造两个动作。

**共享目录/任务/媒体声明**：目的地清单的列数由 `nodePlan` 声明；普通命名目的地每项不超过64字可用2–4列，正文长句保留单列，HTML 不再私自用12字阈值折回目录。已有 `_composite:login` 选择紧凑认证页框，字段标签在输入上方、同组字段等边；这不声称复现认证后端。集合成员图像与节点已有导航标题目标共享链接，不从图像URL推断目标或添加源外动作。

 **目标保真**：共享 `hasTarget` 支持 HTTP(S)、已声明内部路径/`key:` 与无空格的 `mailto:地址`；不接受 javascript/data/file 等协议。选择选项的目标随 `choicePlan` 进入对应选项，而不是因变成 radio 就丢掉；HTML 在该选项保留真实链接（不声称 radio 自动执行导航），Markdown 保留同一选项目标。无采集目标的选项不得发明 URL。正文 email 链接与其他句内链接保持行内。

## 5. 标题与区域边界

- 标题（h2/h3）**管辖其下全部内容**；
- 不同的已填充兄弟区域即使同名也保留本地标题；不得用全页“已见标题”集合抹掉后续组的归属。深层 H4/H5/H6 仍至少为正文的 1em，不随模型嵌套层数缩为 10px。
- 若某区块没有标题，而它前面的区块有标题，必须输出**区域分隔**（`<hr class="region">`）或给它一个位置标签，
  否则读者会把无标题内容归入上一个标题；
- 纯标题无内容 = 广告/promo 块（F-030/T-106），不是章节标题。

### 5.2 容器按内容收缩，不出现"宽框空右半"（轮 27b 明文规则）

一个**带外框**的容器（fieldset/卡片）若内容很少而框铺满可用宽度，右侧就是死空，读者会把空框当"内容缺失"。
规则：**带框容器默认按内容收缩**（`fieldset.expose.chipbar{display:inline-block;max-width:100%}`），只有内容本身
需要满宽的表（`<table class="data">` 选择表/数据表）才铺满。选择该实现而非"让内容铺满"的理由：单选组/筛选行的
成员是**短标签**，把它们拉开放满只会制造更大的空洞；收缩后框紧贴内容，长列表仍靠 `max-width:100%` + 成员换行自适应。
实测覆盖：`apple-com/ipad-air` 5 个单选组、`36kr-com/search-*` 的 search-type/sort 两行、`huawei-cn/search-*` 的 `类别`。

### 5.3 标题来源：可见文本优先，文档标题需注明出处（轮 27b 复核）

- H1 用**抓取可见文本**（`nodes.json` 中可见的标题/页头文案）；
- **确无可见标题**才用文档 `<title>`，且 `_intent` 必须注明来源与"无可见标题"的证据；
- 不得由截图或 SEO 串接串**编造**标题。

**首段规则（轮 46 明文规则）**：回退到文档 `<title>` 时，H1 **取首段**——按 `|` / `｜` / `_` / ` - ` 切分后的
第一段。理由：站点把「页面名 + 站点名/口号」拼成 SEO 串（`Xiaomi官方网站 | 以人为中心…`、`华为 - 构建…`、
`36氪_让一部分人先看到未来`），整串当 H1 会把口号/Slogan 读成标题。完整标题**不丢弃**，作为 provenance 写进 `_intent`。

复核结果：`36kr-com/{home,information-technology,search-ai,search-viz}` 已注明（合规；轮 46 起统一取首段）；
`mi-com/home` 补记来源并取首段「Xiaomi官方网站」；`mi-com/shop-category-list` 改用可见文本「全部商品分类」（原为文档 `<title>`）。

**站点身份不是页面大标题（用户确认）**：Apple 首页和淘宝首页的根级站点名称作为紧凑的站点身份呈现，并对齐本站内容边缘，不能任意放大成巨型页面 heading。共享 `pageLayoutOf` 在营销/目录页面结构中，根节点自己的动作是无独立文案的 `navigate` 时，声明 `headingRole: identity`；HTML 保留可发现的根 heading 和真实导航目标，但使用 18px、左对齐的 `.site-identity`，其余产品/文章标题不受此规则压小。判定不认站名，不增加模型表现键；站点名称事实仍须保留。

**层级塌陷**：`_primary` 的 hero 放大只适用于**短值/数字**。一句**导语**（长文本）若按 H1 字号（2em）渲染，
页面就没有了真正的标题层级；故长句 `_primary` 降为可读导语字号（`.hero-prose`，1.15em/600），实测修 `linear-app/home`。

### 5.1 空 promo 盒：没有图就不成其为广告位（轮 27 明文规则）

`bareTitle`（只有标题、没有任何其它内容）**只在源站有图**时才成立：有图 ⇒ 用图（`promo promo-image`）；
**没有图 ⇒ 不是广告位**，标题按普通文本/小标题渲染（它是那一条内容本身），**绝不渲染成空灰盒**。

- 实测（轮 27 全库探针）：`bareTitle` 命中 **8 处**，**8/8 都是 `_lines`/`_items` 里"只有名字、没有 `_detail`"的普通成员**
  （`13” model` / `P3 wide color` / `Answer calls and texts` / `Bigger, brighter Liquid Retina display.` …），**没有一个是带图广告位**。
- 因此这条规则同时修掉"空 promo 盒"缺陷族，且**不**改动任何带图块的渲染。

## 6. 暴露字段按类型渲染真实控件

- `type: date` ⇒ `<input type="date">`，`num` ⇒ `number`，`text` ⇒ `text`，`secret` ⇒ `<input type="password">`；
- `secret`（密码/秘密输入，闭式枚举新增值 · 轮 46）：渲染为 **password** 控件，**其取值永不进入条件语法/日志/aria/文本目标**
  （HTML 不写 `value`/`aria`，文本/Markdown 目标只出占位 `(密码)`）。仅“秘密输入”用 `secret`；普通文本框不得用它（它只是把明文换成密文，不改变“文本输入”语义）。
- 只有一个选项的"选择"不是选择 ⇒ 渲染为规格行（`颜色：白色`），不渲染成不可用的单选；
- 标签与提示必须在控件上（legend/hint），不能让用户看到两个无归属的日期。 ← Airbnb 入住/退房
- 数据表保留全部列，窄屏通过有界 `.data-scroll` 横向滚动（表最小 640px）而不是挤成孤立单词列。丰富选项表的 fieldset 同样有界滚动，显式移除浏览器 fieldset 默认 min-content 下限，防止整页溢出；文字/标签/选项关联不丢。
- 图片对应的 definition 行按标题/图像成组、从顶部开始阅读；全图像的 named collection 用紧凑 caption 格，图像等比缩到至多 360px 高（永不放大）。真正榜单仍保留位次；长标签/短日期值在窄屏堆叠，不能把日期拆成四行。

### 6.1 搜索框：标签作水印、提交控件必须出现（轮 27b · 用户 D-3 裁定）

用户裁定原文：*"一个搜索框应该有一个名称和一个默认值；如果没有给默认值、只给了名称，可以考虑把名称当作默认值
水印在框内节省空间；也可以考虑把它放出来，得看编排引擎怎么思考。"*

启发式规则（共享判定 `choicePlan().labelAsPlaceholder`）：

1. **可搜索的复合结构若有提交动作 ⇒ 提交控件必须出现**，不得只剩一个裸输入框（提交控件的分组/主次仍走 §4.2 的 `actionRow`）；
2. **标签优先作为 placeholder（水印）**：`type` 为 `text`（或未声明）且带 `_label` 时，`_label` 写入 `placeholder`
   并把 `aria-label` 一并保留；不再另起外部 `deflabel`；
3. **外置标签的例外**：`date`/`time`/`num` 这类控件水印语义不成立（`type=date` 本就有自己的 UI），仍外置标签；
4. 纯文本/Markdown 无"框内水印"概念，标签仍紧邻输入记号出现（等价表达，不丢标签）。

实测覆盖：`36kr-com/search-*`（`请输入关键词` → placeholder，`站内搜索` 与输入框同栏）、`huawei-cn/search-*`、`bilibili-com/home`（`磊哥游戏` → placeholder）。

## 7. 图像主导页 = 满幅

若页面的可信内容主要是图像（正文在图片里，如小米首页、米家净化器），则主视觉必须**满幅**（edge-to-edge），
不得在中间放一张小图、四周留白——那与源站语义完全不同。截图派生的图片资产允许（`_image.source = screenshot`），
但**不得**从截图转写文字（F-025 仍然有效）。

### 7.0 图带是页面的框：展开到视口宽（轮 34 明文规则）

「满幅」不是「铺满文本栏」。图带（`figure.strip`，即图像主导页的主视觉带）的真实宽度是**视口宽**：
`width:100vw` + `margin:0 calc(50% - 50vw)`，左右**不留白边**。实测（1280 视口）：改前 `mi-com/home` 10 條图带均为
**x 110..1170（宽 1060）**（该页文本栏 1100 − 2×20 内边距），改后均为 **x 0..1280（宽 1280）**，`scrollWidth == clientWidth`。

例外：**卡片/表格/推广盒内部的图不是页框**，保持容器宽（`.cards .strip,.run .strip,.promo .strip,.cmp-table .strip,.defval .strip,td .strip`）。

另外两条与「空白」相关的硬规则（轮 34）：

- **整幅纯白的裁切带不得当内容渲染**（它不是图像内容，而是采集空洞）。若空白在裁切图像是里并且该区域确有内容 ⇒ 重裁到内容边界；
  **若整条带都是空白（无内容可裁）⇒ 从模型移徐该带**，并把采集缺口记到 `m1/failures.md`（源站懒加载区块未绘制是采集问题，不是排版问题）。
- **页尾不得留 >80px 空尾**（`main` 的下内边距 80px 是排版间距，不是空白）。
- **长串纯标签（≥6 项、每项只有名字）是清单，不是目录**：渲染成等格清单（`.manifest`），不编 1..N 号。
  编号会把「一组面板名」读成「章节目录」（实测 `grafana-play/play-home` 的 11 个面板名）。

### 7.1 图片保持自身比例、且**绝不放大**（轮 27 规则 + 轮 45 修订）

- 图片默认 `width:auto; max-width:100%; height:auto`：于是**实际显示宽 = min(naturalWidth, 容器宽)**——
  容器比自然宽更窄时才收缩（不留横向灰底）；自然宽 < 容器时**按自然尺寸显示，绝不拉伸**。
- **绝不**用 `object-fit:cover` 限高：那会**裁掉内容**（长图两侧/上下被切），是丢信息，不是排版；
- 因此**不设固定高度**（没有 letterbox、没有裁剪），图片高度由比例决定；
- **例外**：`deflist` 的 `.defval` 行内缩略图（图 + 一个控件成一行，如 apple 服务区）保持自身宽度，
  它是行内小图不是区块主视觉。
- **轮 45 新增**:**不放大是硬规则**（F-082）。旧规则 `width:100%` 会把 234×176 的源缩略图拉到容器宽
  （2~3 倍放大、发虚），并把每条列表项撑高，页面被无谓拉到 1.4 万像素。
  实测（1280 视口，playwright 量 `naturalWidth` vs `displayed`）：`bilibili-com/read-home` 的 19 张
  `@234w_176h` 封面由 `234×176 → 677×509` 改为 `234×176 → 234×176`，页面总高 **14394px → 8060px**；
  全库放大张数 `19 → 0`（`bilibili-com/home` 的 516✗290 横幅也从 516→677 的放大中修正）。
- 轮 27 的实测（42 页 `naturalWidth/Height`）：改前 22 张图被 `height:150px + object-fit:cover` 裁剪
  （aliyun 首页 6、apple 首页 16）；改后全库 0 张被裁。
- **引擎落点**:`render.mjs` 的 `img{max-width:100%;width:auto}` 与 `.fact img` / `.cards img` /
  `.promo-image img` / `.strip img` 四条同规则。**门禁**:`m1/eval/no-upscale-selftest.mjs`——**构造**
  `200px` 宽图 + `1000px` 容器，在 Chromium 中量得显示宽 `≤200px`（回归 `width:100%` 时立刻 FAIL，
  实测被量到 `677px`）；Chromium 不可用时退化为同一 CSS 的非静态级联断言。

## 9. 轮 30 明文规则（价格限定词位置 / 去重 / 数值角色标签 / 卡片主视觉）

### 9.1 价格限定词的位置是词本身的语法（`qualifierPlacement`）

一个 `{money}` 的 `qualifier` 放在数额**前**还是**后**，不由渲染器随手决定，而是这个词在自己的语言里
**读法**决定的（共享决策 `axis.qualifierPlacement`）：

- **后置**（中文下限/每单位副词）：`起`、`含税`、`每月`，以及任何 `每 X` / `per X` / `each` 形式的按单位词
  —— 例：`RMB 6799 起`、`$0.09 每 GB`、`£50 per certificate`；
- **前置**（其余一律）：`从`/`From`、`起始价：`、`订金`、`3.4% +` 等**带标签或费率**的限定词
  —— 例：`From $749`、`起始价：HK$4`、`订金 ¥9.9`、`3.4% + HK$2.35`。

默认前置，只有明确的“后置词”才后置。修复的现象：`apple-com-cn/iphone-17` 曾渲染成 `起 RMB 6799`，
源站是 `RMB 6799 起`。若某限定词的读法无法判定，就按源站原文顺序处理。

### 9.2 同一节点内同一金额只渲染一遍

一个节点的主视觉（`_primary`/hero 的 `{money}`）与正文里**逐字复述同一金额**的文本事实（如 `_summary` 含
`RMB 6799 起…`）同时存在时，**只留一处**。优先保留信息更全的一处：`_summary` 是模型事实、必须逐字渲染
（保真门禁），且比 `_price` 多带 `RMB 284/月`，因此这里**去掉重复的 hero 行**，`_price` 的金额仍由摘要
承载、事实不丢（`m1/curated` 未改动）。修复现象：`iphone-17`/`ipad-air`/`macbook-air` 的价格出现两遍。

### 9.3 数值角色事实带共享词表标签（`quantityLabel`）

`_count`/`_measure`/`_rating`/`_rating-count`/`_stock` 这类**数值角色事实**若在
`m1/vocab-role-labels.json` 有非空标签，渲染时前缀该标签（`数量 20.2 万` / `规格 155`），让裸数字有归属；
**没有词表标签的就不加**（不发明）。例：bilibili 视频卡的播放/弹幕数。

> **轮 32 修正**：只有**语义无歧义**的数值角色才自动加标签：`_rating`→评分、`_rating-count`→评价数、`_stock`→库存
> （`_price` 的金额格式自带单位）。`_count`/`_measure` 是**通用计数**，站点语义因页面而异——bilibili 视频卡的 `_count` 是
> **播放量**、`_measure` 是**弹幕量**，套上通用词「数量/规格」会让读者以为 155 是手机规格，**比裸数字更误导**（组 2/3/4
> 独立同结论）。因此 `axis.quantityLabel` 的自动前缀集不含 `_count`/`_measure`（见 `NUMERIC_LABEL_KEYS`）：
> **默认不加**，除非模型显式给出自己的 `_label` 文案；二者仍可作**数据表列头**（表格里“数量/规格”是有归属的列名）。

### 9.4 重复的标题/控件（同容器内）

- **标题**：与**祖先**标题逐字相同的标题不再画（保留外层）；与**本页已出现过的**标题逐字相同、且该节点
  **自身没有事实**（只是一个带控件的分组标签，如「更多指南」下的「支付方式」）时也不再画（保留第一处）。
  带事实的同名标题属于不同小节，保留。两种情况文本都仍在页面上，保真不受影响。
- **控件**：同一节点的动作行里 **label 与目标都相同**的控件只出现一次。**目标不同**的同名控件（如 sspai
  每条各自的「来源」外链）**不是**重复，**不得**合并——合并会删掉真实链接。

### 9.5 卡片/列表条目的主视觉图（轮 30 放宽；轮 39 再放宽并改为“条目内最大图”）

条目（卡片/列表行）的**首个视觉元素**若是图片，**且 `w≥120 且 h≥120`**，即可作为该条目的主视觉图挂载
（此前判据 `w≥200` 把 mi「猜你喜欢」10 张 140×140 商品图排除在外）。**轮 39 放宽**：卡片/列表条目的主视觉图放宽为
**`w≥100 且 h≥60` 且该图是该条目内“最大的图”**（同一容器内按面积最大者）。"最大"这条是用来**排除头像/图标**的：
条目里同时有 19×24 头像与真内容图时，只有最大者才是主视觉（否则头像会顶掉缩略图）。**一致性检查**：同一行/同一组的图片
**高度方差不得过大**（T-105 `img-variance`：组内 `min/max < 0.7` 即判硬缺陷）；若某组方差超标，回滚该组并报告。
本轮的 10 张 140×140 均为 1:1、同一缩略变体，渲染后等高。实测（轮 39）：`bilibili-com/read-home` 的 117×88 视频缩略图
（低于旧下沿 120，但是其条目内最大图）可挂；同一列表里的 24×24 头像（条目内非最大图）不可挂。

### 9.6 形态选择不得吞掉已声明的图/动作（轮 32）

**形态服务内容，不能删内容**。一个集合成员只要带 `_image` 或 `_action`，就**不得**被选成折叠（accordion）：
折叠面板只画“标题 + 详情”，会把该成员的图与控件**静默丢弃**。判定：`selectForm` 的 accordion 分支要求每个成员
**既无 `_image` 也无 `_action`**，且只有 `_title`/`_detail`（无子节点）；否则按卡片/列表渲染并**保留图与动作**。
实测：`huawei-cn/home` 的「推荐信息」4 条（模型里各带源站图 + 「了解更多」外链）曾被折叠成 `<details class="qa">`，
**丢掉 4 张图与 4 个链接**；修正后渲染为卡片，4 图 4 链接均在。真 FAQ（标题+详情、无图无动作）仍走 accordion。
门禁：`axis-selftest.mjs` I0–I2（构造集：带图+动作 ⇒ 非 accordion 且图/动作计数正确）。

### 9.7 图片归属：四条手段，且锚点必须是**包含性**的（轮 42；F-081）

**给抓取到的内容图归属到模型条目**时，`m1/eval/imgattr.mjs` 按序**穷尽**四种手段，命中唯一才写，并列即记
`SKIP-…-ambiguous`（从不按索引/DOM 顺序猜）：

| # | 手段 | 判据 |
|---|---|---|
| M1 | **业务键** | 图的**包含性** `<a href>` 的键集（query 值、路径 basename、id 段）∩ 条目 `_action.to`/`_key` 的键集，唯一命中 |
| M2 | **alt == 标题** | 源站 `alt`（归一化）逐字等于条目标题 |
| M3 | **包含性锚点名** | 图**包含性** `<a>` 的可访问名（去 `最新/新品/热销…` 徽标前缀）以条目标题为前缀，**最长标题胜出** |
| M4 | **几何序 y 带** | 显式 `--only=<集合路径>` 开启；条目数与候选数相等且同一 y 带（跨度 ≤4000px），否则记 skip |

**为什么不能只用“最近的（前置）锚点”**：旧扫描器（轮 38 的 `.scratch/38-images-sweep/imgattr.mjs`）的低层分词器在遇到闭合标签时
`continue`（**不把它们记成 token**），于是祖先栈**从不弹栈**——所谓“祖先”退化为**文档序里最近一个仍未闭合的开标签**，
也就是“**最近的前置 `<a>`**”而非“**包住这张图的 `<a>`**”。后果：一个在卡片链接**之后**、位于普通正文块里的图，会被
**错挂到那条链接的条目**上（轮 41 实测：aliyun 4 张图的锚点 `href` 恰好等于**另一个已带图条目**的 `_action.to`；
mi 商品详情长图被复制进“7天价格保护”条目）。修法：`scanDom` **记录闭合标签并正确弹栈**，并对外报 `dangling-open-tags`
——**非 0 即拒绝输出任何映射**（栈在撒谎，祖先链不可信）。锚点的可见文本按**它自己的 `</…>` 位置**截断（`closeEnd`），
不再越过锚点去吞下一个兄弟节点的文字。

工具：`node m1/eval/imgattr.mjs <corpus-dir> <model.json> [--minw] [--minh] [--only] [--yband] [--json]`，
输出**候选 ⇄ 条目映射 + 每条归属证据**（method、条目路径/标题、图 URL/尺寸/bbox、包含性锚点的 href 与可访问名、祖先链）。
自测：`m1/eval/imgattr-selftest.mjs`（13 条断言：嵌套 `<a>`、闭合后不继承的回归、未闭合标签计数、`<picture>` 多源、
条目内多图、锚点文本不越界、端到端 M3）——已注册为流水线第 8 道自测门。

## 8. 引擎与模型的职责边界

- 模型声明**意图**（`_items` = 可互换实例；`_lines` = 有序序列；命名子组 = 分区）；
- 引擎负责**轴决策**（行/列/表格/控件条）并自判可比性；
- 模型把不可比内容放进 `_items` 是**策展缺陷**，引擎必须能自愈（降级为序列），同时记录 ticket 回改模型。
- 实测（F-031 落地时的宽松判据）：55/98 个集合属于"放进 `_items` 但不可比" ⇒ 自愈必须存在，且需一轮策展回改。
  - **口径说明（轮 7-8 更新）**：上列 55/98 用的是早期宽松判据（把纯标签集合也算进分母）。改用**引擎自身的可比性判据**（`selectForm` → `stack`）后，策展页的不可比集合为 **23 个**（含 n=1 与 expose 组）；其中候选 **12 个**：**6 个已回改为 `_lines`**（确属异质），**6 个经判据分析保留 `_items`**，1 个豁免（成员级 `_expose` 的独立开关组）。任何引用本节的数字都必须注明所用判据，否则两个口径不可比。
  - **重要区分（轮 8 发现）**：`comparable()` 的**紧凑度门槛**（`max(childCount) ≤ 2`）是**表现**判据，不是语义异质证据。集合可能"同形（`avgSim = 1.000`）且同粒度"却仅因成员各自带 >2 个子块而落入 `stack`——此时 `_items`（同类可互换实例）仍是**说真话**的声明，`stack` 只是富成员的**表现降级**。
    因此 `stack` 这一个输出混了两种不同原因：**语义不可比**（应改模型）与**表现太富**（模型正确，引擎降级）。M4 若引入卡片/网格类原语，必须把这两者分开表达（例如 `_rel.detail: "rich"` 或让原语自己声明成员可入格），否则会把"表现降级"误当成"模型有错"。

## 9. 正文链接 vs 动作控件（轮 35）

同一个 `<a>` 在两种角色下必须长成两个样子，判据是**它的语义角色**，不是它恰好是链接：

- **正文链接（inline link）**：链接是句子的一部分——读者顺着上下文读到它，点开是补充信息。它必须留在正文**行内**（与周围文字同一基线与字号，仅用颜色/下划线区分），**不得**被抽成独立一行、更不得套上按钮外观（描边胶囊或实底色块）。把正文链接画成按钮，读者会把它读成页面的动作控件，句子也被割断（gov-uk `category letter` 一类的行内引用）。
- **动作控件（action control）**：链接本身就是**要执行的控件**（提交/购买/翻页/跳转到另一页），脱离上下文也能独立成立，才用控件外观（`render.mjs` 的 `.ctl` 胶囊 / `.action` 实心）。

**引擎落点**：`render.mjs` 里正文事实（`.fact`/`.prose` 的 `.val`）内的链接一律行内显示；只有 `_action` / 动作行（`renderControls`、`actionRow`）才产出 `.ctl`/`.action`。**模型落点**：把"补充信息的引用"建模为正文的一部分（`_text`/`_summary` 等文本里），不要拆成带 `_action` 的独立条目；只有真正的翻页/跳转控件才建 `_action` 条目。

**判定条件（轮 46 明文规则，为什么旧规则没生效）**：轮 35 只规定了“正文链接要行内”，但**没有给出引擎能自判的判据**——`gov-uk` 的 `approved translator`/`apply for a UK passport` 被建成节点自己的 `_action`，于是 `actionRow` 一律当动作控件画成实心按钮（终审 g3）。现补上可计算判据（`axis.inlineBodyLinkKey`）：
一个 `_action` 的 `label` 若是本节点某条**正文文本事实**（`_detail`/`_summary`/`_text`）的**真子串**（即它出现在句子里，而非独立成句），它就是**行内链接**：HTML 在该句内把 label 渲染成 `<a class="body-link">`，**不**再产出 `.ctl`/`.action`；文本/Markdown 目标保持原句、不另起控件行。`label` 整句等于正文（标题即控件）或等于 item 名（标题控件）的不适用。实测：`gov-uk/register-birth-abroad` 的三个句内引用改行内，实心按钮只剩真正的 CTA `Start now`。门禁：`axis-selftest.mjs` P0–P2。

**行宽测度（measure）**：普通内容的 `.fact`、`.prose` 最大行宽为 **74ch**，文字从所属页面框架左边缘开始，不能把 prose 单独居中而让相邻标题/表单偏到另一条轴。表头/卡片/营销 hero 不受此限。长篇阅读页由共享轴层 `readingPageOf` 判定（至少 8 个超过 120 字的 `_text` 段），根容器使用统一的 **800px 上限阅读列**，在窄屏随容器收缩：封面、正文、混合列表、预告、标签和讨论共享左右边界，不因局部形态切换宽度；其内部事实/段落不再重复收窄。一屏 1000+px 的正文行是可读性缺陷，不是“用满宽度”。

**导航与页脚密度**：轴层 `utilityGroup` 标记短标签/品牌事实集合（至少 2 项、每项文本不超过 32 字、无其他事实或命名子件）；HTML 紧凑折行，较长类目清单使用自适应多列。短标题/值事实序列通过 `utilityFacts` 收紧纵向间距，但不改变其顺序、不声明横向对比。没有记录性元数据、每项文本 ≤64 字的图卡集合可使用紧凑媒体格；图仍不放大。Footer 使用紧凑折行分组和浅中性 surface，不把辅助信息当深色营销横幅；所有事实和目标链接保留。

**当前用户场景与反馈（用户确认）**：主要屏幕宽度为 2560px；已查看的七页（`sspai-com/post-114716`、`taobao-com/home`、`mi-com/product-detail-mi15`、`apple-com/home`、`apple-com/ipad-air`、`airbnb-com/room-28871`、`bilibili-com/home`）除 Apple/淘宝站点身份标题外，当前体验可接受，应保留，不做无必要的重新设计或回退。Apple 原站黑色营销面板可以 full-bleed 到视口边缘，这本身不是缺陷，不作为必修项。其余现有策展画廊页面须应用这些视觉原则；不增加新站点，也不把 auto 辅助快照作为用户交付页面。验证宽度为 2560 / 1920 / 1440 / 390px；整页体验审查、相关源站与图片对照、事实/动作保真和独立技术/体验复核均不可由几何检查或既有门禁替代。

**页面级对齐与超宽屏**：共享轴层 `pageLayoutOf` 从结构选择布局契约，不按站名分支。页面标题、导语、动作和相邻混合形态的 section 继承所属页面框架的共同起始边缘；局部 `w-prose/w-narrow/w-wide` 分类不再选择独立的居中宽度。默认框架仍为 1280px 上限、24px 内边距；文字行保持阅读测度，表格在同一 heading 下面可用框架宽度。长篇仍使用阅读列；至少 6 个价格节点且至少 3 组纯标签菜单的目录页，导航、促销与商品区继承同一页面框架；根节点同时有图与价格的商品叙事页，所有正文 section 继承 960px 上限内容列，不再在 880px / 1232px 间切换。至少两组带图与动作的一级营销故事，使用同宽面板和产品网格；当前实现的整页框架最大 1728px（内宽 1680px），1920px 及以上左右为稳定浅中性 gutter；这描述当前已接受的实现，不是禁止 full-bleed 的视觉原则。原站 full-bleed 营销面板可以保留，不能仅因到达视口边缘判为缺陷，也不为恢复 full-bleed 而无必要地回退当前设计。图像本身不放大。带照片集合与 `form` 命名子区域的详情页，照片在共同框架上，正文与任务面板在桌面并列，后续区域在底部；900px 及以下恢复单列。网页上的“居中”指共同容器居中，不要求每段文字都居中。

**Surface 配色**：背景与前景成对使用 `--surface/--ink`，次级文字使用 `--muted`，软底块使用 `--soft/--soft-ink`，边界使用 `--line`。`brand-tokens.json` 保留采集到的原始前景色及来源，不把它伪称为浅色背景的可读配色。HTML 的普通链接 accent 在白色 surface 上以同比缩减 RGB 通道亮度直到对比 ≥4.5:1，保留来源色相；这不是复制源站完整主题，需实际页面复核。营销媒体区域仍消费自身成对的前景/背景声明。页脚在同一区域覆盖整组变量，不能只反转文字、留下白底浅字 chip。营销媒体的底色/前景由 `m1/media-surfaces.json` 声明（原始图片边缘采样和内容包围盒，非业务模型颜色）；图片、标题、文案、控件组成同一 panel。已有 Apple 三幅媒体保持原始图片 URL，按自然高度居中显示，桌面裁去的仅为内容包围盒之外的左右纯背景；手机按至多 0.7 比例缩放，并由内容包围盒限制缩放比例以免裁掉产品。媒体元数据尚只覆盖这三幅，不宣称自动识别所有图片。

## 10. 轮 37 明文规则（引导语/脚注顺序 · 榜单编号 · 默认值 · 标签 vs 水印）

### 10.1 集合的引导语紧邻集合，脚注在集合之后（`nodePlan().facts.trailing`）

**现象**：`gov-uk/register-birth-abroad` 的引导句 `This birth certificate should be accepted in the UK, for example when you:`（源站的 `<p>` + `<ul>`）与它自己的项目符号列表被拆开——节点的 `_detail` 脚注插在引导句与列表之间（源站顺序是 `引导句 → 列表 → 脚注`）。

**判据（声明顺序 = 源站顺序）**：同一节点内，**声明在集合键（`_items`/`_lines`）之后**的描述事实（`_summary`/`_detail`/`_text`）是该集合的**脚注**，渲染在该集合**正下方**；声明在集合键之前的描述事实是**引导语**，渲染在集合**正上方**。引擎**不得**把所有正文事实统排到集合之前——那会让脚注割裂引导语与列表。共享决策落在 `axis.mjs` 的 `nodePlan().facts.trailing`（三个目标都拿到它；HTML 消费它画出先后，文本/Markdown 的事实块仍按声明顺序输出，事实不丢）。**注意**：事实的声明顺序既是本规则的依据，也是各渲染器早已依赖的顺序，故这是"读同一份顺序"，不是新语法。

### 10.2 只有**声明为榜单**的有序集合才编号（`rankedSequence`；轮 39 由推断改为声明）

**现象**：轮 35 给 36kr「24小时热榜」加序号的逻辑（`order === "sequence"` ⇒ 编号）套到了 `huawei-cn/home` 的 hero 轮播上，首屏出现 `1. / 2.`。

**判据（声明优于推断）**：序号是**榜单**语义，因此榜单必须**声明**出来：`_rel.order = "rank"`。
- `"rank"` = **榜单/排行榜**：条目是**同类、可排序**的条目 ⇒ **应编号且允许带图**（轮 39：36kr 热榜首条源站就有缩略图，
  按旧规则“带图就不编号”会把 1–8 的位次弄丢）。
- `"sequence"` = 展示顺序（轮播/首屏/特性带，成员一般是各带自身 `_image` 的视觉促销图）⇒ **永不编号**——
  给横幅轮播编号会被读成目录页。

故：`axis.rankedSequence(items, order) = order === "rank" && items.length > 1`；`axis.selectForm` 把 `rank` 与
`sequence`/`time` 同视为有序集合（不塌成一行 chip）。共享判定在 `axis.mjs`，`renderDeflist` 只消费它。
**轮 37 的旧表述已废弃**：由 `order === "sequence" && 无成员带 _image` **推断**“是不是榜单”，等于用“有没有图”
猜“是不是榜单”——榜单一旦挂图就丢编号（不可陈述的规则）。现在由模型**声明**，闭式枚举加一项 `rank`（`validate.mjs` 同步）。
实测：36kr 热榜 8 项在 `rank` 下**既编号又带 1 张缩略图**；`huawei-cn/home` hero（2 项）与 `apple-com/macbook-air`
特性带（6 项）仍是 `sequence`，不编号。门禁：`axis-selftest.mjs` L0–L5。

### 10.3 抓取到的输入框默认值必须作为 value 呈现（既有键 `_text`）

**现象**：`36kr-com/search-*` 的源站 `input` 有 `value="人工智能"`/`value="数据可视化"`，我们渲染成空框。

**规则**（用户 D-3："复合元语应有名称与默认值"）：一个裸文本输入节点的 `_text` 事实是它的**当前/默认值**，渲染为该输入框**可见的 `value`**（`choicePlan().value`）。**只补抓取里真实存在的默认值**，不发明。裸输入以 `_text` 优先、既有合法 `_default` 为后备；secret 输入两者均不输出。选择集合以捕获的 `_default` 精确匹配选项文字或 `key:` 标识，显式上下文同名值优先；未匹配不猜选项。HTML 保留 checked，Markdown/文本保留选中记号；选项目标仍由独立真实链接表达，不声称切换选项执行后端导航。此处使用现有闭合语法，不新增键或站点模板。可见文本口径下 `pageText` 不读属性，故值在文档里另留一份 `.sr-only` 文本（同 §6.1 水印名的做法），事实不丢。

### 10.4 §6.1 修订：只在源站**没有可见标签**时把名称当水印

**现象**：`stripe-dashboard/login` 的源站有独立可见标签（`<label>` 邮件地址 / 密码），却被降级成框内 placeholder。

**判据**（D-3 原话："没有给默认值、只给了名称 ⇒ 可把名称当水印"）：`_label` 是**可见标签**（命名了字段主语的名词：`邮件地址`/`密码`/`Username`/`分类`/`颜色`…）时**保留可见标签**；只有当 `_label` 是**占位/示例文案**（源站没有可见标签：`请输入关键词`/`搜索专栏文章`/`站内搜索`/`说点什么...`/`磊哥游戏`）时才把名称水印进框内。共享判定 `axis.isVisibleFieldName` 修正 §6.1 的 `labelAsPlaceholder`：`labelAsPlaceholder = 文本输入 && 有 _label && !isVisibleFieldName(_label)`。实测：`stripe-dashboard/login`、`github-com/login`、`xiaomi-account/login`、`mi-com/{product-detail-mi15,search-earbuds}` 恢复可见标签；`36kr`/`huawei`/`bilibili`/`mi search-phone`/`sspai` 的搜索框仍走水印。

### 10.5 时间流文本（弹幕/滚动评论）限量+紧凑，不铺成竖排墙（轮 46 明文规则）

**现象**：`bilibili-com/video-bv1gj411x7h7` 的弹幕样本 44 条被 `renderChips` 判成 `chips-rows`（成员含《》？！等句读⇒每条自成一行），铺成 ~50 行竖排文本墙（终审 g3）。

**判据（声明，不推断）**：把一条**时间流文本**（弹幕、滚动评论、直播聊天）**声明**为 `_rel.order = "stream"`。引擎据此把它渲染成**行内紧凑流**（`.stream` → `.stream-item`，`flex-wrap` 多行多列，每条 `white-space:nowrap; text-overflow:ellipsis` 限一行），**不再**一条一行。这正是 §1 的“行=可比”原则：弹幕不是可比的记录，把它逐行编号/竖排会读成目录；行内流保持“一串短句”的观感。与 `order: time` 不同：`time` 是有序内容清单（时间线，走 `seq`/`.timeline` 竖排），`stream` 是**短文本流**（走 `.stream` 行内）。仅“成员都是裸标签（`_name`/`_title`/`_text`）”的集合走 `.stream`，带结构/带图/带动作的集合仍走原形态（不吞事实）。模型侧声明：`m1/curated/bilibili-com/video-bv1gj411x7h7.json` 的 `danmaku-sample`。门禁：`axis-selftest.mjs` R0–R1。
