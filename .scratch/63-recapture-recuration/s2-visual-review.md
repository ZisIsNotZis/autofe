## Regressions introduced / exposed by this pass

- **huawei home flattening:** 我们的业务 six icon cards → one row of small pills; 新闻动态 six-card grid → plain text list. Both bands lost the information presence the source homepage has; the pills look like tags, not a business matrix.
- **huawei home footer:** source's structured 5-column link grid became cramped small-print paragraph lines — reads broken.
- **bilibili read-home page type:** ranked list → excerpt-heavy 4-col card wall; long grey excerpt text is content the source rows don't display (fidelity risk as well as a type mismatch).
- **sspai matrix aside displacement:** all right-rail content (一图, 值得关注, 专题推荐) is stacked below the feed as plain rows; feed thumbnails detached at the far right edge. (Deferred region concept, but the current output is visibly wrong, not merely simplified.)
- **apple comparison table duplicate labels:** every row shows its label twice (left rail "显示屏" + cell "显示屏", same for 芯片/摄像头/电池/Apple 智能) — a data-model artefact leaking into the render.
- **sspai profile stats row:** six equal boxes for very unequal facts, one literally "暂无徽章 0" — box filler that reads as stub.

## Top 5 remaining gaps for S3 (typography/colour/surfaces), ranked by visual impact

1. **No display type anywhere — one flat 2-step ladder.** Every h1/h2 on all 10 pages sits ~16–20px over ~14px body (apple's 搭起来，炫出来。 is 48px+ gradient display in the source; our version is a small bold line). Fix: a real modular scale per page type (display 40–64px, ≥3x body), weight contrast (300 vs 700), `text-wrap: balance`. This single change moves every page.
2. **No band/surface system — every page is a white document.** Sources are built from alternating full-bleed bands (apple grey/white rhythm, huawei photo bands, mi section tints); renders have one white background with hairline cards, so nothing paces the scroll. Fix: 2–3 surface tokens (page / band-grey / card) + full-bleed band wrappers, so hero/feature/footer bands are distinguishable at squint distance.
3. **Brand colour is absent; links default blue.** sspai/bilibili card titles and many links render unbranded blue; mi's orange survives only as bullet dots; huawei red only in footer links. Fix: per-site ink/accent tokens (sspai near-black titles, mi orange, huawei red, bilibili pink) + one link style; kill the default blue.
4. **One utilitarian button on every brand.** The same black rectangle serves 购买/了解更多/前往购买/充电/进一步了解 across apple, huawei, mi, sspai. Fix: brand-shaped actions (apple pill, huawei red pill, mi orange) with a size scale; secondary actions as text links, not boxed.
5. **Media scale and placement.** Thumbnails and product cards are systematically undersized versus image-led sources (search thumbs ~90px beside 6–8-line text; huawei catalogue cards a quarter of the source's tile size; matrix thumbs detached at the container edge). Fix: per-page-type media ratios (search ≥160px, product tiles ≥220px, feed thumb bound to the text block, not the canvas edge) and an even vertical rhythm token instead of content-driven gaps.

## Was the deferred feed+aside (matrix) visibly wrong?

**Yes.** The source is a ~65/35 two-column page (feed + sticky rail with 作者一图/值得关注/专题推荐); the render is a single full-width stream, with the rail's content stacked underneath as unstyled rows and the 一图 image as an orphaned centred block. Even judged as a deliberate simplification, the page currently reads as a bare search-results list — the feed+aside region concept is needed before S3 polish, or S3 will style a wrong skeleton.
