## D-1（最重要）是否为复合原语引入 `_macro` 保留键？
**同类待决项（先看这三条失败记录）**：`m1/failures.md` **F-047**（`qualifier` 取值发散）、**F-048**（`list` 是引擎硬编码的临时语义 token）、**F-050**（`paginator` 的“当前页/被分页集合”没有现成表达位）——都与 D-1 同属“闭式化需拍板”。
**背景**：M4 提案里有 5 个复合原语（`form`/`table`/`offer`/`paginator`/`login`）。它们的**行为**可以用现有键实现（已在做），但"命名原语 + 良构校验"需要一个标记键。

- **选项 A（建议）**：新增保留键 `_macro`，取值是**闭式枚举**；展开规则是**恒等展开 + 良构检查**（校验通过后原样返回子树）。
  - 关键性质：**不增加任何表达力**，只**增加校验强度**（"声明了 `form` 却不满足 form 条件"变成硬错误）。
  - 与我们的哲学一致：闭式 + 无逃生口 + 每一条声明都可被校验。
- **选项 B**：不加键，原语只作为文档里的"良构配方"存在，引擎按约定识别。代价：无法强制，声明与实现可能漂移。
- **选项 C**：只给 `table`/`form` 两个加（它们最需要强约束），其余不加。
- **不决定的后果**：M4-b 只能交付"行为改进"，不能交付"可校验的原语声明"；提案 §5.3 的第 3-6 步无法按设计落地。

## D-6 金额字形与精度策略（第 8 轮验收发现，**唯一与"逐字照抓取"有字面偏差**的地方）
- 现象：源站写 `每 GB USD 0.00` / `USD 0.085`，我们渲染成 `$0` / `$0.085`——**币种 token 被换成符号**，且 `0.00` 的尾零被去掉。这是库级既有约定（不是某轮引入），但按我们的公理"抓取即真相"它是**转换**。
- **A（建议）**：模型记录**源站自己的币种 token**（如 `currency:"USD"` + 可选 `display:"$"`），引擎**默认原样输出**；只有声明了 brand token 映射时才替换字形与精度。理由：与"闭式 + 不发明"一致；`¥99` 这种源站本就写符号的情况不受影响。
- **B**：维持现状（引擎统一用符号），把它当作 M5 品牌层的既定呈现策略，并在文档里**明确声明这是有意的转换**。
- **C**：模型直接存字符串金额（**不采用**：会丢掉金额的机器可读性）。
- **不决定的后果**：不阻塞；但"逐字"类宣称必须加限定语（目前已在 `layout-axes`/报告中标注）。

## 用户裁定记录（2026-10-01，远程口头；逐字要点 + 父代理落地口径）

### D-1 → 采纳**精神否决"macro"命名**，改为 **Schema 式复合元语**
用户原话要点：
> "Macro 这个我不是很明白……听着非常像黑魔法，就不像我们这种优雅的形态。复合元语不是本身就是一个组件信息的感觉吗？它没有参数校验之类的吗？什么叫做缺少必要的部件？我觉得这种复合元语应该本身就类似于 **Schema** 的感觉。"

**落地口径（本次实现必须遵守）**：
- **不叫 macro、不做"恒等展开"**。复合元语 = **一个声明式类型**；每种类型在**闭式词表**里定义 **schema**（必需字段/可选字段/允许字段/它暴露什么状态）；
- 实例用 `_composite: "<类型>"` 声明，**校验器按 schema 逐项校验实例**（缺必需字段 ⇒ **类型错误**，与 JSON Schema 校验对象同构）；
- 因此"缺少必要部件"= **schema 里声明的必需字段缺失**（用户问的正是这个：以前结构没有"类型"，所以无从判断完整性）。
- 用户举例：**搜索框就是一个复合元语**，它的 schema 至少有 **名称** 与 **默认值**；若只给名称不给默认值，**可以把名称当作框内水印（placeholder）**——具体由编排引擎决定（不写死）。

### D-2 → **允许下游引用**，且要**路径访问**
用户原话要点：
> "复合元语只是把一堆元语封装成一个复合元语，它也有字段、词汇……你完全可以通过这种 **点 A 点 B 点 C** 这种方式访问到里面的子属性。像 login 的密码，这种保护属于 **edge case**，可以有，但不是重点，暂时不保护问题也不大。"

**落地口径**：路径语法（如 `form.size`、`search.query`）可被 `_when`／`_action.when` 引用；**不为 secret 做特殊保护**（记为后续可选加固）。

### D-3 → 采纳 A（闭式词表标签 + 可覆盖），并加"标签→水印"编排规则
用户原话要点：
> "搜索框本身肯定是一个复合元语，它应该有一个名称和一个默认值。如果没有给默认值、只给了名称，可以考虑把名称当作默认值水印在框内节省空间；也可以考虑把它放出来，**得看你的页面编排引擎怎么思考**。"

**落地口径**：标签来自闭式词表且可被 `_label` 覆盖；**标签→placeholder 的降级是引擎的编排决策**（不写死，可在文档里作为一条启发式）。

### D-4 → 采纳 A：**先不扩样本**，优先"把现有页面做到完美"
用户原话要点：
> "样本我感觉可以先不急着扩充，**先把这几个页面做到完美再说**。现在至少我上一次看，**很多地方说不过去**。"

**落地口径**：质量优先于覆盖扩张；本轮已启动 4 个**视觉审美评审**（`.scratch/25-quality/findings-1..4.md`），结果驱动修复轮。

### D-6 → **币种是标准枚举；字形是风格/用户偏好，不进元语**
用户原话要点：
> "这些金额其实无所谓，显示 USD 也好、显示 `$` 也好，不都是一个风格吗？……每个国家 `$` 都可能代表各自的元，所以这玩意儿更像是一种**风格/用户偏好**，而不是在源语里写死的。源语里**撑死就是币种**，币种可能是一个标准枚举。"

**落地口径**：模型只存**标准币种枚举**（ISO 4217 类）；**字形（`$`/`¥`/`US$`）与精度展示属呈现层/品牌层**（M5），由偏好/品牌 token 决定，不写进元语。因此我们当前的 `USD→$` 映射**不再是"偏差"**，而是"默认品牌风格"——只需**声明化**（可配置），并在"逐字"类宣称里注明这是呈现层选择。
