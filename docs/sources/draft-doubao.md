# 前端业务模型驱动渲染架构 · 设计白皮书（最终对齐版）

## 一、传统前后端架构核心痛点（本次架构要彻底解决的问题）

### 1\. 接口语义贫瘠，只有数据、没有业务

传统 RESTful 接口只返回原始 JSON 数据，**只描述 “值”，不描述 “意义”**：

- 后端无法定义：哪个字段是摘要、哪个是详情、哪些数据是指标、哪些是文本描述

- 前端需要人工硬编码解读数据含义、业务关系、页面角色

### 2\. 业务逻辑严重耦合在前端

所有交互规则、展示规则、业务约束散落前端代码：

- 哪些可点击、哪些禁用、哪些需要展开、哪些是图表、哪些是列表

- 字段展示 / 隐藏、按钮可用 / 不可用，全部前端写死

- 导致：改业务 = 改前端代码，页面泛滥、版本混乱、业务不统一

### 3\. UI 与业务强绑定，无法千人千面、无法动态编排

传统开发是**前端写死页面结构、写死组件、写死布局**：

- 同一套业务无法根据设备、用户偏好、场景自适应渲染

- 无法 AI 排版、无法自适应 PC / 移动端、无法个性化界面

### 4\. 前后端职责严重错位

- 后端只给裸数据，不定义业务规则

- 前端被迫承担大量**业务建模工作**（本不该属于前端的工作）

- 导致：业务逻辑分散、BUG 分散、权责混乱

### 5\. 页面元素定义混乱

传统页面是「UI 组件堆砌」：banner、卡片、tile、按钮、列表
**全部是视觉概念，不是业务概念**
导致：换样式、换组件、换布局 = 重写前端逻辑

## 二、本架构核心设计哲学（绝对顶层原则，不可推翻）

### 哲学 1：**后端只定义【业务事实】，绝不定义【UI 表现】**

- 后端不讲：全宽、网格、卡片、按钮、图表、隐藏、折叠

- 后端只讲：这是什么业务、有什么数据、能不能操作、是什么业务角色

- **所有排版、布局、组件形态、视觉样式，全权交给前端编排引擎**

### 哲学 2：**业务与表现彻底解耦**

- 业务语义稳定、长期不变

- UI 渲染、布局、样式、动态效果可无限迭代

### 哲学 3：**一个业务元素 = 最多一个业务动作**

- 视觉上多个按钮 = 模型里多个独立业务元素

- 杜绝单元素多行为，保证模型极简、逻辑自洽、无歧义

### 哲学 4：**结构即关系，不做额外引用、不做冗余 ID**

- 页面层级嵌套 = JSON Key 天然树形层级

- 禁止全局 ID、Ref、跨节点绑定

- 仅跳转场景使用**路径寻址**，无额外寻址体系

### 哲学 5：**机器语义纯英文、人工注释纯备注**

- 引擎解析关键字、枚举、条件表达式：全部英文标准化

- 人工理解内容：使用 JSONC 注释，不污染模型结构

- **彻底废除 hint、UI 描述、前端专属词汇**

### 哲学 6：**拒绝大杂烩字段，数据字段平铺化**

- 废弃统一 `data` 大包对象

- 所有业务字段平铺：`_title` / `_subtitle` / `_summary` / `_text`

- 结构直观、可扩展、无嵌套黑盒

## 三、全新架构核心思路（范式革命）

### 1\. 彻底推翻传统前后端分工

- **传统**：后端给数据 → 前端写页面、写业务、写交互

- **新范式**：后端输出【完整业务模型】→ 前端通用引擎全自动渲染

### 2\. 业务模型：只包含三层逻辑（逻辑分层，结构一体）

> 逻辑三层，**物理不拆分、不独立、不引用、不混乱**
> 
> 

1. **业务数据层**：真实业务字段、数值、文本

2. **业务语义层**：定义当前元素「业务角色」（是什么）

3. **业务动作层**：定义当前元素「能做什么、在什么条件下做、跳转到哪里」

> **彻底移除：前端渲染提示、布局提示、UI 偏好**
> 所有渲染决策由前端引擎全权负责
> 
> 

### 3\. 页面本质重构

- **传统页面**：一堆 UI 组件的组合

- **新架构页面**：**一棵标准化业务语义树**
页面不存在 UI 概念，只存在「业务元素 \+ 业务关系」

### 4\. 前端彻底业务无代码

- 前端不再写任何页面业务代码

- 前端只维护：渲染引擎、AI 排版管线、组件映射、适配规则、用户偏好系统

## 四、严格统一的设计约束（强制规范）

### 1\. 字段命名约束

- 无前缀 Key：**子业务元素**（代表层级、代表页面结构）

- 下划线 `_` 开头：**当前元素元属性 / 业务字段**

- 禁止自定义乱写字段

### 2\. 元素行为约束

- 单个元素：**0 或 1 个 Action**

- 多交互 = 多元素，不允许单元素多动作

### 3\. 语义约束

- `_semantic`：纯英文业务角色枚举，**无任何 UI 含义**

- 禁止出现：`PROMO`、`BANNER`、`CARD`、`GRID`、`FULL_WIDTH` 等前端词汇

### 4\. 跳转寻址约束

- 废弃 jumpKey、label、hint、tag

- 内部跳转：基于树路径寻址 `a.b.c`

- 外部跳转：直接写路径 / URL

- 无跳转：`to: null`

### 5\. 注释约束

- 所有人工说明、设计说明、备注：使用标准 JSONC `//` 注释

- **模型数据层绝不存储人工备注字段**，彻底废弃 `_comments` / `note`

### 6\. 彻底废除的所有旧概念

- 废弃三层物理拆分

- 废弃 ID /nodeId/ref

- 废弃 hint /displayHint/ 任何前端偏好

- 废弃 actions 数组

- 废弃大包裹 data 对象

- 废弃中文条件、中文动作、中文引擎关键字

## 五、架构核心目标

### 短期目标

1. 实现**业务 100% 由后端收敛**，前后端业务逻辑不再不一致

2. 实现**页面零前端业务代码**

3. 实现复杂页面（首页、详情页、看板、官网页）纯模型驱动

### 中期目标

1. 前端引擎实现**全自动排版、自适应布局、设备适配**

2. 支持用户偏好动态差异化渲染（千人千面）

3. 支持 AI 智能排版、组件自动择优

### 长期终极目标

**彻底消灭页面级前端开发**

- 新增业务页面 → 后端输出业务模型即可上线

- 前端只做底层引擎迭代，永不参与业务页面开发
