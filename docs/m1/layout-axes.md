# 布局轴语义（F-031 · 元语层结论）

背景：人审指出「四列 Finish / Storage / Trade In / Payment 毫无排比关系却在同一行」「单元格窄到一行只有一两个词」「横向对比被折到第二行」「一个 Header 下面没东西就进入下一区域，会被误认为属于上一个 Header」。
这些不是排版参数问题，而是**元语缺失了"轴"的语义**。

## 1. 轴即语义（不可由宽度决定）

- **同一行** ⇒ 成员**可比**：同类、同形、同粒度，可横向对照。
- **同一列（堆叠）** ⇒ 成员是**顺序**或**并列但不可比**的区块，各自独立成立。
- 因此：**列数不能由容器宽度决定**，必须由语义决定；宽度只决定"排得下几列"。

推论（引擎必须遵守）：
1. 只有"可比"的成员才允许进入行布局；
2. 不可比 ⇒ 堆叠，每块**自带标题**；
3. 无标题的堆叠块必须显式区隔，否则会被读成上一个标题的下属内容；
4. 行内任何成员不得因列数过多而被压到"一行一两个字"——**宽度不足就减少列数，不是压窄**。

## 2. 可比的判据（可计算，引擎自判）

成员集合 S 进入行布局当且仅当：

| 判据 | 含义 | 阈值 |
|---|---|---|
| **同形** | 成员的类型化字段/事实键集合一致（Jaccard） | ≥ 0.6 与集合中位数成员相比 |
| **同粒度** | 成员的信息量接近：文本长度、事实数、有无子节点 | 文本长度比 ≤ 3× 且事实数差 ≤ 2 |
| **紧凑** | 单个成员适合放进格子 | 文本 ≤ 160 字、子节点 ≤ 2、图片 ≤ 1 |
| **同高** | 渲染后成员高度接近 | 行内最高/最矮 ≤ 3× |

任一不满足 ⇒ 该集合是**区块序列**，堆叠渲染。

反例（本轮实测）：
- 苹果 iPhone 16 六步（Finish/Storage/Trade In/Payment/Connectivity/Carrier）：字段键几乎不重叠、单格高 786px vs 1667px ⇒ 序列，必须堆叠；
- 少数派 114716 正文 17 段：非同类、长文本 ⇒ 序列，堆叠为阅读宽度；
- 36kr 频道 17 项（纯标签、同形紧凑）⇒ 真可比 ⇒ 允许行布局（chip 条）。

## 3. 横向对比 = 表格，且**不换行**

`_rel.compare` 的成员是"被对照的实体"（如各机型）。合规形态：

- **列 = 实体**（每个实体一列，列头是实体名/价格/标签）；
- **行 = 属性**（Display / Chip / Camera / Battery …）；
- 实体的个数决定列数，**不因宽度折到第二行**；宽度不足时**横向滚动**，绝不换行；
- 当前浏览对象用标记（如"当前浏览"）出现，不是重复内容。

## 4. 控件不是内容

`_action`-only 的成员（加入购物车 / 喜欢 / 修改 / 立即领取）是**控件**，必须渲染为控件条（链接样式，可点击感），
**不得**混入 chip/内容条目。控件若有抓取到的目标地址 ⇒ `<a>`；无目标 ⇒ 保持链接观感（不造 `<button>`）。

## 5. 标题与区域边界

- 标题（h2/h3）**管辖其下全部内容**；
- 若某区块没有标题，而它前面的区块有标题，必须输出**区域分隔**（`<hr class="region">`）或给它一个位置标签，
  否则读者会把无标题内容归入上一个标题；
- 纯标题无内容 = 广告/promo 块（F-030/T-106），不是章节标题。

## 6. 暴露字段按类型渲染真实控件

- `type: date` ⇒ `<input type="date">`，`num` ⇒ `number`，`text` ⇒ `text`；
- 只有一个选项的"选择"不是选择 ⇒ 渲染为规格行（`颜色：白色`），不渲染成不可用的单选；
- 标签与提示必须在控件上（legend/hint），不能让用户看到两个无归属的日期。 ← Airbnb 入住/退房

## 7. 图像主导页 = 满幅

若页面的可信内容主要是图像（正文在图片里，如小米首页、米家净化器），则主视觉必须**满幅**（edge-to-edge），
不得在中间放一张小图、四周留白——那与源站语义完全不同。截图派生的图片资产允许（`_image.source = screenshot`），
但**不得**从截图转写文字（F-025 仍然有效）。

## 8. 引擎与模型的职责边界

- 模型声明**意图**（`_items` = 可互换实例；`_lines` = 有序序列；命名子组 = 分区）；
- 引擎负责**轴决策**（行/列/表格/控件条）并自判可比性；
- 模型把不可比内容放进 `_items` 是**策展缺陷**，引擎必须能自愈（降级为序列），同时记录 ticket 回改模型。
- 实测（F-031 落地时的宽松判据）：55/98 个集合属于"放进 `_items` 但不可比" ⇒ 自愈必须存在，且需一轮策展回改。
  - **口径说明（轮 7 更新）**：上列 55/98 用的是早期宽松判据（把纯标签集合也算进分母）。改用**引擎自身的可比性判据**（`selectForm` → `stack`）后，策展页的不可比集合为 **23 个**；轮 7 已回改 10 个，**12 个待回改**（其成员需要各自的 `_intent`），1 个豁免（独立控件组）。任何引用本节的数字都必须注明所用判据，否则两个口径不可比。
