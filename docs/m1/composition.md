# 页面构图与意图校验（composition）

状态：当前事实（就地重写，不带历史叙事）。
溯源：构图层缺口由 10 页视觉诊断确认（证据：`.scratch/63-recapture-recuration/design-diagnosis.md`）；本文件是该层的唯一事实家，诊断记录只作证据不作事实源。

本层回答一个问题：**页面级「怎么排」由谁定、如何保证引擎真的做到了。** 它位于「业务语义（模型）」与「DOM/CSS」之间。

## 1. 语义归属 vs 形态：谁声明、谁决定

- **页面语义归属（scope/subject）是闭式业务事实，必须由模型声明**。它回答「这是站点入口、某一分类、一次查询、一个实体、一份文档、还是账号/表单」以及「主体是商品/dataset/文档/账号」。
  - 证据：仅凭业务结构推导，10 类里只能干净分出 5 类，40 页最好 20/40 与 19 页残留；`landing/home` 与 `category/list` 同构（12 页，同站成对）、`product-detail` 与 `article/editorial`/`table-heavy` 同构。这不是阈值问题，是缺一个语义位（`.scratch/63-recapture-recuration/composition-derivation-analysis.md`）。
  - 它是**闭式枚举**（如 `_composite`），不是 UI 旋钮、不是逐页手写样式；由采集/策展依据源站页面角色自动填入。
- **布局框架与媒体角色是引擎的形态决策**：同一 scope/subject 可以由引擎选不同的 band/网格/阅读列；模型不表达这些。
- 因此本层既改引擎（构图推导与框架），也向语法加**两个闭式语义键**；不加任何表现/样式键。
- 反例：在模型里写 `_kind: "catalog"` 或每页 CSS，是表现混入语义或站点级逃生口，仍禁止。

## 1.1 两个闭式语义键

| 键 | 闭式取值 | 含义 |
|---|---|---|
| `_scope` | `entry` / `category` / `query` / `entity` / `document` / `account` / `form` | 页面在站点中的角色 |
| `_subject` | `offer` / `document` / `account` / `dataset`（可缺省） | 页面的主体种类 |

采集 archetype → 语义键的映射（迁移依据）：

| 采集 archetype | `_scope` | `_subject` |
|---|---|---|
| `landing/home` | `entry` | — |
| `category/list` | `category` | — |
| `search-results` | `query` | — |
| `product-detail` | `entity` | `offer` |
| `article/editorial` | `document` | `document` |
| `docs/design-system` | `document` | `document` |
| `profile/account` | `account` | `account` |
| `table-heavy/admin` | `entity` | `dataset` |
| `dashboard/data-viz` | `entity` | `dataset` |
| `form/checkout/settings` | `form` | — |


## 2. 构图必须完备，不得静默回落

- 每个页面解析出恰好一个页面原型（闭式集合：`reading` / `catalog` / `marketing` / `detail` / `product` / `authentication` / `search` / `profile` / `table`），否则是**显式错误**。（`feed` 不是独立原型：它是 §3 里 catalog / feed / search 共用的框架族，今日语料 0 页需要单独原型。）
- `default` 不是合法结果。解析不出原型 = 引擎错误（门禁失败），不是「普通页」；门禁在渲染上要求页面带上与其原型对应的页级类（`reading-page` / `<kind>-page`）。
- **覆盖口径诚实**：40/40 是「声明 → 投影」检查，不是「从结构推导出原型」——40 页都声明了 `_scope`/`_subject`，因此测度分支在真实语料上 0 次触发；结构规则与含混负样本由自测行使（`composition-selftest.mjs`）。声明的**正确性**是策展事实，门禁只能保证声明不被静默改写。
- **唯一实现**是 `m1/axis.mjs` 的 `pageLayoutOf`（返回 `kind` 与裁定它的 `rule`，裁不出时 `kind` 是 `undefined`）；门禁 `m1/eval/composition-selftest.mjs` 在 pipeline 里运行，断言 40 页各自落在其采集 archetype 的允许集内，并用含混负样本证明树会诚实返回 `undefined`。
- 判定依赖业务结构（角色、`_lines`/`_items` 层级、`_rel`、关系、复合件）加两个闭式语义键（scope/subject）；**不得**依赖站点名或逐页例外。声明与偶然计数不可互换：声明了 scope/subject 的页面由声明裁定，计数（长段数、价格数、横幅数）只在未声明角色的页面上兜底——否则 4 个商品页会被长段数判成阅读页。
- 长文/阅读型判定统计**全部长文本**（`_text`、`_quote`、`_summary`、`_detail`，嵌套含 `_lines`），不得只看单一字段。

## 3. 布局框架（frames）是一等概念

页面原型映射到真实框架，而不是把一切倒进同一个文档列：

| 原型 | 框架 |
|---|---|
| marketing / landing | band 序列（满幅或色带）+ 居中/交替排版 |
| reading | 居中阅读列（单一 measure，hero 收敛到该列） |
| catalog / feed / search | 卡片网格 / 记录行网格；feed 用「主列 + 侧栏」两区（判定见下条：只在 catalog 原型上，`search` 保持结果行） |
| detail | 媒体墙 + 主列 + 任务卡（右侧或栏内停靠） |
| profile | 居中身份卡 + 统计块 + 活动 feed |
| authentication | 居中表单卡 |

- **区域（region）**：主列与侧栏是两个区域，侧栏内容不得在单列流里掉到正文之后。
- **feed + 侧栏（两区帧）**：页面主体是**一个占优的集合**（成员数 ≥8 且 ≥ 次大集合的 2 倍）时，排在它**之后**的**短卡片小节**（单张卡片，或成员 ≤6 的短集合）进右栏（380px，滚动停靠），feed 占左主列；排在它之前的小节（视图切换、创作入口）留在主列、feed 之上。判定全属引擎侧（`m1/axis.mjs` 的 `feedRailOf`，规则名 `feed-and-side-cards`，模型不新增键）：同站没有站点名、没有逐页例外。两个反例保持单列（自测负样本）：并列集合（两个 feed 而非 feed+侧栏）、以及本来就有自己帧的原型（`search` 的结果行、`marketing` 的 band 序列不重切成两区）。链接列（纯目的地列表）与长文小节不是侧卡，留在主列、跟在两区之后，不因帧判定被吞掉。**覆盖口径诚实**：40 页里只有 `sspai-com/matrix` 触发（1/40），其余 39 页的单列形态不变。
- **入口矩阵的列数整除入口数**：营销页 ≥4 个带目标控件的矩阵按入口个数取列（6→3 列、8→4 列，素数走均衡拆分 7→4+3），不留 4+2 的偏行；判定是 `m1/axis.mjs` 的 `matrixColumns`，落成容器上的 `--matrix-cols`。窄视口降为 2 列 / 1 列。
- 区域按声明角色取宽；页级框架决定对齐基线，局部表单不得各自选宽（沿用 `docs/m1/layout-axes.md` §5.2「容器按内容收缩」）。
- **认证页框宽度盛得下它自己的句子**（S5b）：`authentication` 帧是 `--auth-width`（28em＝476px），不是随手取的 440px。依据是量出来的：`xiaomi-account/login` 的协议行「☑ 已阅读并同意｜小米账号使用协议｜和｜小米账号隐私政策」按 17px 正文需 **428px** 内容宽（复选框 13 + 文字 102 + 链接 136 + 「和」17 + 链接 136 + 4×6 间距），而 440px 框的内容盒只有 400px（−24 内边距 −2 边框）——短 28px 就把它挤成逐字断行。框宽只保证常用句子一行（Chromium 实测：1280 视口下标签 426×75 两行、逐项断字 → 461×45 一行）；更长的句子由控件自身的 `.choice{flex-wrap:wrap}` 在**成员之间**断行，不逐字断。
- **记录行按自身量宽封顶**：一行 = 文字列（`--measure-row`）+ 媒体槽（216px）+ 声明间距（24px），整行 `max-width` 取这三段之和；拉得比这更宽，未用的中段就是文字与图之间的空白。媒体留在源站那一侧（feed 右、搜索结果左）。
- **内容列居中，不贴左**：行封顶后整**列**按同一量宽居中（`margin-inline:auto`），不贴左留出一条半页空带；列宽由行决定（无媒体的记录行 ⇒ 文字测量宽，带媒体的行 ⇒ 三段之和），行填满列，同列各行左边缘因此对齐。搜索结果行用更宽的文字测量 `--measure-search`（38em：结果块是「标题 + 3 行夹紧摘要 + meta」，取 CJK 行长上限），feed 记录行用 `--measure-row`。片框比列宽时左右余量对称，不再是一侧的空白。表页的小节标题与其下的表前导语同列居中，表格本身仍满幅。
- **页面量宽与页边：内容坐在中央一条带里，不贴边**（S6）：页框不是「吃满 1280」，而是 `--page-measure`（1160px，1120–1200 区间）这条内容带 + `--page-pad`（`clamp(24px,4vw,72px)`）两侧页边；`main` 的外盒 = 带 + 两条页边。1280 视口下内容落在 x=60..1220（两侧各 60px 余量），1920 下 380..1540（带宽不变 1160）。满幅带与页脚仍可逃到视口（`width:100vw` + `margin-inline:calc(50% - 50vw)`），但带内文按内容带对齐。营销页的 band 序列保留自己的宽帧（`main:has(.marketing-page)`，1280 下内容 1178px），页边同一把尺。依据是量出来的：旧页框内容 1232px、左边距 24px，aws 表页与 sspai 个人页因此「页面感觉顶到边」。**不缩阅读/搜索的文字测量**：`--measure`（36em）、`--measure-row`（59ch）、`--measure-search`（38em）都是 em/ch 尺，与页框无关。
- **页级孤立控件居中，不贴左**（S6，owner 裁定）：页级（root 的直接子元素、页级节点的直接子元素）单独成行的 `.action` / `.action-plain` / `.controls` 在比容器窄时居中——容器居中、块内文字仍左对齐；绝不留「控件贴最左、右侧半页空白」的注意力拖拽。量出来的证据：36kr 搜索页根级 `SPAN.action-plain`（查看更多）在 x=24、右侧 1117px 空着；`sspai-com/matrix` 的「开始创作」、`taobao-com/home` 的「搜同款」同形；`gov-uk` 的单个 ctl、`linear-app/home` 的 Get started 是一整条贴左的控件条。两个例外是关系约束而非风格：标题与品牌标识保持页面基线左边缘（那是排印基线，不是孤立控件），直接拥有单行字段的节点把提交钮留在字段那一行（`span.expose-input`/`expose-select`/`.fieldbar` ⇒ 36kr 搜索的「站内搜索」跟在输入框后）。判据与负样本在 `m1/eval/taste-selftest.mjs`（第 18 道门禁，几何量 40 页 + 合成贴左负样本）。
- **页脚是一条居中带，链接组在带内分布**（S6）：页脚铺到视口，内文内边距取 `max(页边, (视口 − 页框内容宽)/2)`，于是无论页框是 1160、阅读列 612 还是认证卡 476，页脚内文都落在该页自己的内容带左边缘；页脚的链接行（`.controls`）是 auto-fit 网格，链接组按带宽分布，不是一条贴左的短列表。量出来的证据：36kr 页脚 6 个链接挤在 x=24..520、右侧 700px 空着；现在 11 个链接铺在 60..1220 的 7 列里。mi 页脚本来已是 4 列（`flex:1 1 250px`），分布形态不变。
- **瀑布流（waterfall）**：成员高度无法等高的卡片集合用 column 流（`break-inside:avoid`），不用行网格——行网格把短成员垫进空洞、让最长者给整行定行距。列数由容器宽与卡片最小宽（280px）算出，不写死：1160px 页框 4 列、852px 2 列、342px 1 列。判据在 `render.mjs` 的 `masonryOf`，全属引擎侧、模型不新增键：① 成员文字量差距过大；② 营销页的图片卡片墙（页框没有给卡片媒体声明比例框，高度由原图比例决定）。候选容器仅是页框真会排成多列行网格的集合（轴层声明的列数，或 catalog 页框自己的多列网格）。统一网格（catalog 卡片的媒体框声明为 4/3）保持行网格。
- **入口矩阵**：营销页一页里 ≥4 个**带目标**的控件是一张入口矩阵（每个入口一张卡），不是一排药丸；动作栏（无目标 / 不足 4 项）形状不变。营销页一个小节的短列表（标题 + 一行事实）是 2–3 列卡片格。
- `[开放]` 「局部最优」布局研究（`docs/sources/design-basis.md` §6）若落地，必须在构建期/缓存完成，运行期只套用方案。

## 4. 媒体角色（media roles）

- 图片按**声明的角色**定尺寸：hero/band 充满其框架；卡片缩略图充满其格子；正文插图受阅读列约束。
- 不得只按原图像素绘制（`width:auto`）而留下白洞或小图。
- 保持「绝不放大源图」判据（`docs/m1/layout-axes.md` §7.1）：按角色布局的是**容器**，图像在容器内等比、不放大。
- 每个角色的**槽**由该角色的文字块决定，不由原图像素决定（S3b）：搜索结果行有 3 行摘要 ⇒ 216px 槽；紧凑记录行只有约 100px 高的文字块 ⇒ 仍用 216px 槽但高度封顶 135px，缩略图不再是一个脱离文字块的 172px 死框。
- **源图小于角色时按源图显示，并记下缺口**（不放大填补）：缺口清单见本节表末两行。

| 角色 | 槽 / 框 | 实测（1280 视口，40 页） | 引擎落点 |
|---|---|---|---|
| 搜索结果行 | `fit-content(216px)` 媒体列 + 高 ≤144px | 216×144（36kr 9+9 张，源 600×400）；78×100（huawei 7 张，源图本身 78×100） | `.search-page .record-member:has(img)` |
| 记录行（feed） | 216px 槽（与文字测量宽 + 24px 间距合成行宽），高 ≤135px | 216×135（sspai matrix 19 张，源 640×400） | `.record-member` |
| 目录卡片 | 4/3 比例框，图像 contain、行高一致 | 199×199（huawei 50 张，源 842×842）；80×80（mi 150 张，源即 80×80） | `.catalog-page .cards .fact:has(>.val>img)` |
| 照片墙瓷砖 | 1:1 瓷砖，首块跨 2×2，图 contain | 304×304 ×4 + 613×613（airbnb 5 张，源 1440） | `.gallery-mosaic .strip` |
| 阅读插图 | 阅读列 612px 内 | 265×150 中位（sspai/bilibili/36kr 41 张） | `.reading-page` |
| hero/band | 满幅框架 | 3008×580 裁于 1280 视口（声明满幅） | `.banner-integrated` |

- 搜索结果行同时把**文字块压紧**：摘要 `-webkit-line-clamp:3`（huawei 5 行 153px → 3 行 92px），216px 缩略图不再被 6–8 行摘要淹没。
- 媒体列用 `fit-content` 而非固定宽：源图本来就小时（78px），固定 216px 槽会把文字推开并留 138px 死格。
- **缺口（角色大于源图，不放大）**：`huawei-cn/search-laptop` 结果缩略图源图 78×100（7 张）；`mi-com/shop-category-list` 商品图源图 80×80（150 张）—— 这两个是采集缺口，不是排版旋钮（见 §6）。`mi-com/search-phone`、`search-earbuds` 卡片图源 800×800 不再被图片封顶（S3c 删除了 `.product-cards img{max-height:160px}`）：实测显示 160×160 = 卡片内容宽（`.cards.compact-media` 的 194px 轨道 − 32px 内边距 − 2px 边框），媒体填满自己的槽、`max-height` 计算值为 `none`，全库放大 0 张。

## 5. 意图校验门禁：声明 → 兑现 → 大声失败

引擎必须把意图说成机器可读的声明（每页原型、每区框架、每媒体角色），渲染后校验计算样式是否兑现；不兑现即错误。三类检查：

1. **未定构图**（`default`）→ **错误（阻断）**。
2. **死选择器**（引擎 CSS 引用的结构类在冻结语料上 0 次打出）→ **警告（不阻断）**。语料不必行使每个引擎能力；把「未被语料行使」当阻断会逼人删掉合法能力。页面原型**已解析却未打出对应类**属于错误（由第 1 项覆盖），与此不同。
3. **死声明**（同一元素上永远不可能生效的重复声明）→ **错误（阻断）**：作者写出了自相矛盾的意图。
4. **运行时意图未兑现**（声明意图的实际计算样式被覆盖 / 在窄视口失效 / 学科缺失）→ **错误（阻断）**。这是自动化版的 DevTools 划线删除；须报出「声明值 / 实际值 / 获胜规则」。

- 阻断项是**线上正确性**（构图未定、意图未兑现、声明自相矛盾）；死代码只作警告，可见但不逼删能力。
- **可证伪**：门禁必须先用已知缺陷做负样本证明能抓到，再谈通过（`docs/proof` 的 gate_probe 原则）。
- 权重口径：与既有「门禁全绿只是必要条件」一致；本门禁只证明「引擎兑现了自己的声明」，不证明设计好看——后者仍靠人审与独立复核（`docs/3_REQUIREMENT.md` (acceptance)）。

## 6. 剩余缺陷（框架 / 设计层）

- **长选项表要开合**（S5b）：选项多到一屏放不下的闭式选择（`sspai-com/login` 的区号 143 项）由轴层判为 `choice.select`，画成一个原生 `<select>`；判据与边界见 `docs/m1/layout-axes.md` §6。
- **采集把展开的面板并成了一个文本节点**（S5b，`sspai-com/login` 的区号面板）：采集拿的是元素的合并文本，所以选项从未以独立元素出现，策展只能从合并串里按「名称 空格 码」逐项重建（144 个空格 = 1 个前缀 + 143 项，逐项配平才认定无歧义）。这是**采集缺口**（面板未逐个元素采集），不是排版旋钮：要根治得让采集把面板选项当元素采。
- 采集的节点文本有 **1000 字符上限**，区号表在「马」处被截断（没有码的半项被丢弃、不补全），故 143 项之后的国家缺失；这是已知缺口，不猜补。
- 侧栏是**结构推出**的两区帧，不是语义声明：`_region` 裁决仍缺；站点导航被捕获成根节点时只能留在主列。
- 卡片的媒体高度在渲染期不可知（模型不带原图尺寸），waterfall 只能用内容量/页框性质作代理，不保证逐页最优列数。
- `search` / `table` / `profile` 原型仍只有通用形态，未到原型专属框架。
- 非记录行卡片的**媒体尺寸不再由图片属性决定**（S3c）：`max-height:160px` 的图片封顶已删除，卡片媒体只受角色槽约束（容器给宽、图等比、绝不放大）。mi 搜索页商品卡当前仍显示 160×160，但那是 `.cards.compact-media` 的轨道（194px）决定的槽宽，不是图片封顶：槽变宽，图随之变大。
- 品味判据的口径限度：`taste-selftest.mjs` 量的是**页级孤立动作与控件条**（`.action`/`.action-plain`/`.controls`）与页脚链接组；表单行（字段 + 提交，`span.expose-input`/`expose-select`/`.fieldbar`）按设计贴内容左边缘，标题/品牌标识同理，两者都不在该判据的家族里（36kr 搜索框、github 登录字段都属于这一类）。合成负样本证明判据能失败；它不证明「好看」，那是人审的事。
- 潜在残留：`.linklist.cols{2,3,4}` 的 `column-gap` 被合并规则的 `gap` 简写覆盖（属性键不同，门禁不报；删除为视觉零变）。
- 观测性：`no-upscale-selftest` 在找不到浏览器时降级为 cascade-only 仍 exit 0；真实无放大证明需带 `AUTOFE_CHROME_PATH`/`AUTOFE_PLAYWRIGHT_CORE`。`manifest.json` 含 `version/generatedAt/mtimeMs`，非内容稳定，故每次 `--shots` 都会改写画廊产物（内容哈希一致时不算证据变化）。

S1/S2/S3 已消灭：构图静默回落、死分支、阅读判定只看 `_text`、死声明、airbnb 照片墙运行时覆盖、320px 封面盖、靠左 hero、record-row 页宽死沟、行网格参差、对比表重复行标题、业务药丸行/新闻流水行、默认蓝链接、2× 字阶（现 h1=3.01× 正文）；S3c：通用蓝 accent（改量品牌 chrome 色，见 `docs/m1/layout-axes.md` §9）、卡片图 160px 图片封顶。S5a：搜索结果列/feed 记录列贴左的半页空带（现整列居中，搜索行文字测量 `--measure-search`）、阅读页里逃出阅读列的满幅 hero 与根级动作、瀑布流写死 2 列（现按容器宽取列）、站名字头 18px（现 clamp 24–32px 品牌头）、营销页嵌套短册表贴左满宽行（现同节卡片格）。S6：页面级「贴边」与「孤立控件贴最左」的品味先验（页框收成 1160px 内容带 + 页边 clamp 24–72px；页级孤立动作/控件条居中；页脚的链接组在带内分布成网格），几何判据由 `taste-selftest.mjs` 量 40 页并用合成负样本证伪；aws 表页、sspai matrix 两区帧、sspai 个人页因此落在中央带内。

## 7. 验收（10 页样板，铺开前）

- 10 个缺陷页作为样板：每页原型非 `default`、声明意图 100% 兑现、门禁负样本全部被抓。
- 交付形态：每页「原站 | 渲染」并排图 + 门禁报告。
- 样板通过后才铺到全部 40 页并重跑全部门禁 + 新独立验收。

## 8. 开放缺口（已知、暂不掩盖）

- **dashboard/data-viz 无语法表达**：语料里唯一的 dashboard 页 `num 0`、无图表/序列/带单位的值原语；它现在只能落到 `table` 原型（框架未实现，S2）。需要一次图表原语的语法演化（n=1，先在结果里记录限制，不假装已解决）。
- **框架缺口**：`search` / `table` / `profile` 原型尚无 CSS 框架（11/40 页带着无效果的页级类），由 S2 落地；门禁只查「CSS → 语料」方向，不查「页级类 → 有框架」。
- **`docs/design-system` 与 `article/editorial` 同属 document**：两者共用阅读框架；`docs/design-system` 在语料里 n=1，暂不单独建模。
- **`table-heavy` 的表「角色」靠位置近似**（深度 1 的表=页级数据集，实体下的表=属性面板）；这是策展纪律，不是不变式。
- **两处建模缺口（不是推导规则问题）**：`sspai-com/login` 缺 `login` 声明（推导按 `_scope:form` 判定）；`mi-com/search-phone` 缺查询态。
- **`search.results` 绑定只有 6 个搜索页中的 2 个声明**（huawei 两页带 `_default` 查询态），其余 4 页靠 `_scope:query` 判定；结构无法自证它们是结果页，故结构规则只认声明的绑定，不退回 facet 代理。
