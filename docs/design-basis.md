## 0. 一句话

定义一套**业务/意图中间语言**，让后端只表达"这是什么、为什么在这儿、能做什么、彼此什么关系"，由**服务端引擎**投影成前端形态；表现与语义解耦。

## 1. 目标与非目标

目标：
- 元语足够 capable，清晰表达业务意图（重点、主次、关系、动作），不表达 UI。
- 引擎把同一模型投影到不同设备 / 品牌 / 用户偏好。
- 能用真实网站**证明**覆盖能力（§7）。

非目标：
- 不追求像素级还原。
- 不做浏览器内运行时渲染（见 §6）。

## 2. 组织框架：意图低维 → 设计流形

**这是组织框架，不是可证命题。** 它不给出内在维度上界，因此不可证伪，只用于组织概念，不作为验收依据。

- 自洽设计只占高维设计空间里一族低维流形；轴间相关（圆角↔阴影↔动效）是流形几何。
- 随上下文变化：设备 / 内容 / 品牌各一张；低维输入必须含上下文。
- 有用的推论：**两张流形 → 两层度量**（§7）——语义有效性（是否忠实表达业务）与表现自洽性（设计是否成立）。

## 3. 模型本体

### 3.1 轴

1. **是什么** — 语义角色。
2. **为什么在这儿** — 意图（定性，如"警示"）+ 优先级（序数）。**两个不同概念，不合并。**
3. **能做什么** — 动作、条件、跳转。
4. **怎么关联** — 关系、分组、比较、时间。

外加**状态**：empty / loading / error / partial 必须可表达（数据驱动渲染绕不过）。

`[开放]` 权限/受众、时间有效性（"三天后开始"）、不确定性（"约"）。

### 3.2 身份与地址

- **身份 = 业务键**（数据层事实，如 productId），唯一、稳定、与角色无关。
- **地址 = 树路径**；一棵树里每个出现只有一条路径。
- 同一元素出现在多棵树 → 用业务键**显式引用**，不是复制。
- 状态（收藏等）挂在**身份**上；优先级 / 角色挂在**地址**上。
- 必须给出解析表：地址 → 身份。**禁止用路径当身份。**

### 3.3 优先级 / 依赖 / 展开

- 优先级只做**同级比较**；模型给的是**默认值**，运行时用户可覆盖（如拖拽排序）。默认 vs 覆盖的语义、用户状态存放位置必须定义。
- 依赖：父级须存在。
- 展开层级由引擎按上下文实时推导，**不写进模型**。

### 3.4 关系约束（语义谓词，不是表现）

模型只写**语义**：这些事实必须**一起被考虑**（比较/共指）、这个**顺序有意义**（序列/时间）、这块**有更深细节**。

可见性 / 并排 / 展开**是引擎的推导结果**；模型不写"滚动""可展开"这类表象。

### 3.5 动作

- **公理层：一个元素恰好 0 或 1 个动作。**
- 嵌套命中区由**降级规则**定义（属引擎契约，不是"以后再说"）：整块可点 + 内部控件如何生成合法 HTML（不得嵌套交互元素）、焦点顺序、点击目标尺寸（可访问性）、内部控件的**事件让渡/穿透**语义。

### 3.6 公理 vs 复合原语

- **公理**：不可再分、正交、少，语义由引擎固定。
- **复合原语**：具名、可完整展开成公理的宏。要求：
  1. 展开全函数、必终止（宏**不递归**；递归只存在于**数据形状**，不在宏展开）
  2. 不新增**语义角色**；分组/关系必须能对应到 §3.4 已声明的关系
  3. 参数有类型
  4. 每个有规范展开式 + 测试
  5. 身份来自业务键，不来自路径
- **一次性 vs 复用**：一次性组合**内联在模型里**（匿名展开），**不**成为新原语；具名复合须达复用门槛（被 ≥N 站点使用）否则删。
- **展开是管线的一步**：可在构建期或运行期调用，结果可缓存。
- 防膨胀：规范化 + 去重审查；具名库有总量上限。

## 4. 表现层

### 4.1 品牌不变量

品牌 = **只改表达、不改语义**的映射；判据 = 互换测试（换任意两品牌仍成立）。不可变：

1. **可达信息**（不是"渲染出的字符"）——须定义截断/展开契约，否则疏密轴会让互换测试必然失败
2. 主次顺序
3. 动作可供性
4. 可访问性
5. 强调的相对顺序 —— **拆分**：颜色强调顺序可确定性测；整体视觉强调只能判（故 M5 不能是纯硬门槛）

品牌 token 与 logo / 商标资产分开：后者是内容引用。

### 4.2 风格轴

品牌 = 一组连续感知轴取值：几何（圆角/线条）、疏密、对比、字、动效、材质、语气。轴间需自洽；模糊标签（"温柔"）用**参考样本对比**判定。

`[开放]` 调性归属：内容是否可给天花板/地板（如庄重场景限制俏皮度）？

## 5. 语法封闭

- 模型严禁自由 HTML/CSS 逃生口。
- **无逃生口 ⇒ 覆盖声明不能靠临时加原语灌水**。（原句"证明强度 = 语法限制强度"是错的：空语言限制最强、覆盖为零。）
- **覆盖只在冻结的语言快照上声明**；冻结后新增原语，之前的通过作废。

## 6. 引擎

- 引擎是**一套同构管线**：`求值(model, context, library) → 渲染`，纯函数、确定、可复现；同一份代码在浏览器与 Node 都能跑。
- **构建期与运行期只是同一管线的两次调用**，不是两套流水线；"预编译上层原语"= 用**同样的管线**跑部分输入，产出可缓存的中间产物。缓存按（输入哈希, library 版本）索引。
- 因为要在浏览器里跑：**语言以 TS/JS 为主**；热点核心**实测过慢**时才下沉为 WASM；起步不用 Rust/C。
- 业务不进引擎：引擎是通用解释器；领域知识/模板/原语是**声明式数据**，不是代码。
- 有利副产品：同构 ⇒ 服务端首屏（SSR）与客户端更新（CSR）共用一套。
- AI 只在**构建期与调试期**；运行期无 AI。
- 用户口味 = 参与编排的参数，不是 prompt。
- 约束优先级：硬约束（可访问性/合规/设备能力）> **品牌定义的可行域** > 用户偏好（在可行域内选点）> 风格口味。
- `[开放·研究]` 布局"局部最优"。目前无目标函数、不可验证；**且若真需运行期重度寻优，会与"在浏览器里跑"冲突**——届时把寻优放构建期/缓存、运行期只套用方案，或该核心下沉 WASM。按实测决定。

## 7. 评测与证明

**oracle 必须独立于布局**：真实基准是人对源页面的**语义角色/关系/优先级**标注；布局只是**输出**，不能当基准（否则把要解耦的耦合又请回来）。

三层度量：
1. **确定性**：信息覆盖、语义角色/关系是否忠实、动作集合、可访问性、颜色强调单调性。
2. **软指标**：数值 + **caveat**（只覆盖已知失真；配 Goodhart 守卫：指标在调语言前冻结，逐指标报置信）。
3. **测不了**：LM judge，oracle = **人工参考对**；禁止拿模型自身当 judge 的参考。

纪律：judge 须用人工标注**校准**并报一致性；pairwise 优于绝对分；逐维度问；不用像素距离；**阈值必须落到数字**。

证明义务：逐站点 pass/fail；**失败必须列出**；区分人工写模型（存在性证明）与自动抽取（实用性证明）；**hold-out 永不参与语法设计**；覆盖率只在冻结快照上算。

## 8. 数据驱动方法

采集管线：渲染 → 清洗 DOM + a11y 树 + JSON-LD + 截图 + bbox/计算样式**对齐**。

注意：bbox / 计算样式是**抽取用的特征**，不是**验证用的基准**（§7）。

采样：先定**页面原型分类**，再跨行业 / 领域 / 风格 / 原型分层采样。合规：robots/ToS/限速；商标仅内部研究。

方法：小样本手看 → 第一版公理 → 手写编码 → **表达失败日志**（写不出来的地方就是缺口）→ 规模到 100+ → 复现缺口升公理、一次性内联。

**公理表是编码过程的输出，不是输入。**

## 9. Milestones（第一大目标 = 元语）

- **M0** 分类 + 分层语料 + 采集管线。判据：覆盖到分类、管线可复现。
- **M1** 第一版语法 + **最小渲染器**（单设备原型）+ 手写编码 5–10 页。判据：**能渲染出来**且匹配标注角色；无逃生口；产出失败日志。
- **M2** 评测台：独立 oracle + 人工标注样本 + 校准过的 judge。判据：定下**数字阈值**；judge–人一致性达阈值。
- **M3** 规模 100+：冻结快照上的覆盖率、失败分类、hold-out 通过率（都给数字）。
- **M4** 复合原语库 + 展开机制。判据：全函数 / 终止 / 规范展开与测试 / 复用门槛。
- **M5** 品牌层 + 不变量测试。判据：可确定性测的部分过硬门槛；强调顺序走 judge（非纯硬门槛）。
- **M6** 引擎：编译 + 服务端确定性求值。判据：**确定性 / 幂等 / 可复现**（同输入同输出）；上下文求值契约明确。
- **M7** 多设备投影。判据：投影不变量（跨设备语义不变量 1/2/3 成立）。

## 10. 开放问题

1. 关系约束（语义谓词）表的完备性。
2. 调性归属（品牌 vs 内容）。
3. 运行期寻优与浏览器性能的边界（决定是否 / 在哪下沉 WASM）。
4. 软指标 caveat 格式 + Goodhart 守卫的具体形式。
5. 风格轴的最小充分集合。
6. 语料规模、hold-out 比例、复用门槛 N 的取值。
7. 权限 / 时间 / 不确定性是否需要进模型。
