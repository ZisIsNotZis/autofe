## 0. 一句话

定义一套**业务/意图中间语言**，让后端只表达"这是什么、为什么在这儿、能做什么、彼此什么关系"，由引擎把它投影成任意前端形态；表现（布局、样式、品牌）与语义彻底解耦。

## 1. 目标与非目标

目标：
- 元语足够 capable，能清晰表达业务意图（重点、主次、关系、动作），而不表达 UI。
- 引擎能把同一模型投影到不同设备 / 品牌 / 用户偏好。
- 能用真实网站**证明**覆盖能力（证明义务，见 §7）。

非目标：
- 不追求像素级还原。
- 不做运行期逐请求 AI 生成布局（见 §6）。

## 2. 核心命题：意图是低维，设计是嵌在高维空间里的一族低维流形

- 自洽、说得通的设计只占高维设计空间里的一张低维流形；轴与轴相关（圆角↔阴影↔动效），这些相关性就是流形的几何。
- 元语是把意图空间映射到该流形的**低维坐标**；引擎负责从低维坐标落到流形上的一个点。
- 修正：
  - **不是一张流形，是随上下文变化的一族**（设备、内容、品牌各不同）——低维输入必须含上下文。
  - **"低维"不等于"有限"**；它是连续流形，重点是内在维度低，不是点的个数少。
  - **DSL 是流形上某区域的一张图卡，不是已证的覆盖**。"流形上任意点都能构造"是**待证命题**，不是前提。
  - 流形随时尚/时代漂移；先验必须可版本化、可重调。
- **两张流形，两层度量**（见 §7）：语义有效性（忠实表达业务）与表现自洽性（设计是否成立）。

## 3. 模型本体

### 3.1 四轴
1. **是什么** — 语义角色（价格、评分、作者、时间……）
2. **为什么在这儿** — 意图 / 优先级
3. **能做什么** — 动作、条件、跳转
4. **怎么关联** — 事实间关系、分组、比较、共现

表现（布局、样式）不属于模型。

### 3.2 身份与地址
- 源语用清晰嵌套树表达主次；同一元素可有多条可达路径（多地址）。
- **地址 ≠ 身份**：引擎内归一到一个稳定身份，用于状态、去重、更新；路径只是地址，用户不碰 ID。
- 同一元素在不同树里扮演不同角色：优先级/角色挂在**地址**上，不挂在身份上。

### 3.3 优先级 / 依赖 / 展开
- 优先级是**同级之间**的比较，挂在地址上。
- 依赖：父级必须存在；或用户须知道其曾存在（如面包屑）。
- **展开层级由引擎按上下文实时推导**，不写进模型；模型只存优先级。
- 展开方式（跳转、小窗、物理展开、滚动……）属引擎编排细节。

### 3.4 关系约束
让"滚动/并排"等表象成立的是**内容性质**，不是表现。候选约束表：
- 基数：有界 / 无界
- 有序：无 / 序列 / 时间
- 共现：是否必须同时可见
- 深度：平 / 嵌套 / 可展开
- 主指：本块的唯一主意图

`[开放]` 这张表的完备性待语料验证。

### 3.5 动作
- **公理层：一个元素恰好 0 或 1 个动作。**
- 嵌套命中区（整卡可点 + 卡内收藏按钮）由引擎规则解决：**最内层可交互节点吃掉事件，外层不触发**。
- 该规则由复合原语的**展开式**定义（写明谁在外、谁在内）。

### 3.6 公理 vs 复合原语
- **公理**：不可再分、正交、数量少，语义由引擎固定。
- **复合原语（定理）**：带参数、可完整展开成公理子树的宏。要求：
  1. 展开是全函数（合法参数 → 合法公理树）
  2. 不引入新语义；只用公理与其它复合原语
  3. 参数有类型
  4. 必须终止（禁递归环或设上限）
  5. 每个有规范展开式 + 测试
  6. 子节点身份由实例路径**确定性**推导
- 防膨胀：规范化 + 去重审查，像审 API。
- **展开时机：编译期全展开。** 引擎把源语编译成 HTML/CSS/JS，计算量可能很大，属离线/构建期管线，不放进浏览器。

## 4. 表现层

### 4.1 品牌不变量（五条）
品牌是**只改表达、不改语义**的映射。判据 = 互换测试：任意两品牌互换后仍是同样成立、同样合格的页面。不可变：
1. 信息内容
2. 主次顺序
3. 动作可供性
4. 可访问性
5. **视觉强调的相对顺序**（色相可换，强调层级不可倒）

品牌 token 与 logo/商标资产分开：后者是内容引用。

### 4.2 风格轴
品牌 = 一组**连续感知轴**上的取值：几何（圆角/线条）、疏密、对比、字、动效、材质、语气。轴间需自洽；"温柔"这类模糊标签用参考样本对比判定。
`[开放]` 调性归属：品牌给默认旋钮，内容是否可给天花板/地板（如庄重场景限制俏皮度）？

## 5. 语法封闭
- 模型严禁自由 HTML/CSS 逃生口；否则"什么都能做"是废话。
- **证明强度 = 语法限制强度。**

## 6. 引擎
- **引擎是构建期编译器，不是浏览器运行时**：源语 → HTML/CSS/JS 的转换计算量大，用高性能语言实现，跑在服务端/构建期；不塞进浏览器或 Node，避免大运行时、库稀少与性能束缚。
- **确定性层**：公理→组件映射、布局、设备投影、主题。可复现、可缓存、可测。
- `[开放]` 目标：布局选择应至少达到**局部最优**——不能被局部小修小改提升清晰度。验证方式待研究。
- **AI 只在构建期**：把经验编译成模板/规则/领域模型/脚本，进仓库、带版本、有测试；调试期由 AI 回看脚本。
- **运行期无 AI。**
- 用户口味 = 参与编排的参数/插件，不是 prompt。
- 约束优先级：硬约束（可访问性/合规/设备能力）> 品牌 > 用户偏好 > 风格口味。

## 7. 评测与证明

三层度量（对应两张流形）：
1. 能准确测 → 直接测（信息覆盖、主次秩、动作集合、可访问性）
2. 能测但不一定准 → 出数字 + **caveat**，交给 judge 专查该失真条件
3. 测不了（意图清晰度、调性、强调）→ LM judge

纪律：
- judge 必须用人工标注样本**校准**，并报告 judge–人一致性。
- pairwise 优于绝对打分；逐维度分开问。
- 不用像素级距离。

证明义务：
- 附原截图 / 现渲染 / 信息量对比，逐站点记录 pass/fail。
- **失败站点必须列出**；只报成功不是证明。
- 区分"人工为站点写模型"（存在性证明）与"自动抽取"（实用性证明）。
- 留一撮站点作 **hold-out**，永不参与语法设计。

## 8. 数据驱动方法

采集管线（无头浏览器）：渲染 → 清洗 DOM + 可访问性树 + JSON-LD + 截图 + 包围盒/计算样式**四方对齐**。对齐把"看起来重要"变成"排得高"。

采样：先定**页面原型分类**（详情/列表/文章/搜索/看板/表单/设置/大表格/落地页……），再跨行业、跨领域、跨风格、跨原型分层采样。合规：robots/ToS/限速；截图含商标，仅内部研究。

方法：小样本手看 → 出第一版公理 → 手写编码 5–10 页 → **表达失败日志**（写不出来的地方就是缺口）→ 规模到 100+ → 反复出现的缺口升为公理，一次性的做成复合原语。
**公理表是编码过程的输出，不是输入。**

## 9. Milestones（第一大目标 = 元语）

- **M0 语料与分类**：原型分类 + 分层语料 + 采集管线。判据：覆盖到分类、管线可复现。
- **M1 第一版语法 + 手写编码 5–10 页**。判据：每页完整编码、无逃生口；产出失败日志。
- **M2 评测台**：确定性指标 + 校准过的 judge。判据：一致性达阈值；软指标带 caveat。
- **M3 规模 100+**：覆盖率、失败分类、hold-out 通过率。
- **M4 复合原语库 + 展开机制**。判据：全函数/终止/有规范展开与测试。
- **M5 品牌层 + 五不变量测试**。判据：互换测试通过。
- **M6 解释器**（确定性布局 + 设备投影 + 主题）。
- **M7 多设备投影与评测**。

## 10. 开放问题

1. 关系约束表的完备性。
2. 调性归属（品牌 vs 内容）。
3. 复合原语展开时机。
4. 软指标 caveat 的格式。
5. 风格轴的最小充分集合。
6. 语料规模与 hold-out 比例。
